# 人物、物品与金币命令

- 兼容等级：B
- 适用入口：NPC 的 `#IF` 与 `#ACT`
- 最后复核：LFM2-2026-08-15-snapshot

## 人物检测

```text
#IF
CHECKLEVEL >= 40
CHECKJOB 战士
CHECKGENDER 男性
CHECKPKPOINTEX < 100
CHECKEXP >= 1000 < 2000
CHECKHP > 0 <= 500
CHECKMP >= 25
```

`CHECKLEVEL` 是现有 `LEVEL` 的别名，`CHECKJOB` 是 `CHECKCLASS` 的别名。经验、HP 和 MP 支持一组或两组“操作符 数值”，两组条件必须同时成立；可用操作符为 `= == != <> > >= < <=`。数值或操作符非法时检测失败并记录诊断，不产生业务副作用。

## PK 点调整

```text
#ACT
CHANGEPKPOINT + 50
CHANGEPKPOINT - 20
CHANGEPKPOINT = 0
```

减少结果低于零时按零处理。负操作数、未知操作符或整数上溢会拒绝本次动作并保留旧值。

## 金币调整

```text
#ACT
GOLDCOUNT + 1000
GOLDCOUNT - 500
GOLDCOUNT = 2000
```

余额范围为 0 至 2,100,000,000。非法参数、下溢或上溢会拒绝本次动作，余额保持不变；成功增减继续使用现有金币同步消息。需要先判定余额时可使用既有 `CHECKGOLD 操作符 数量`。

真实语料高频使用的 `GIVEGOLD` 和 `TAKEGOLD` 继续可用：前者达到项目金币存储上限时只发放可容纳差额，后者请求超过余额时扣除现有全部余额。需要严格拒绝上下溢的迁移脚本应使用 `GOLDCOUNT`。

## 声望调整与检测

```text
#IF
CHECKCREDITPOINT > 9
#ACT
CREDITPOINT + 10
CREDITPOINT - 5
CREDITPOINT = 100
```

`CHECKCREDITPOINT` 是现有 `CHECKCREDIT` 的翎风精确别名，支持 `= > <`。`CREDITPOINT` 直接调整账户已有的持久化声望字段；增加继续发送 `GainedCredit`，减少继续发送 `LoseCredit`。减少超过现有声望时按零处理，增加或赋值超过 `uint` 上限、负操作数及未知操作符均失败关闭。

## 人物名称颜色

```text
#ACT
CHANGENAMECOLOR 249
```

颜色代码按翎风 0 至 255 旧调色板解析，并通过现有 `ColourChanged/ObjectColourChanged` 链广播。选择结果保存在人物私有变量快照中，可随二进制及 SQL 人物变量持久化；默认代码 255 为白色。红名、褐名、战争及敌对行会颜色仍具有更高显示优先级。

## 地图传送别名

```text
#ACT
MAP 0
MAP DB 28 16 3
MAPMOVE DB 28 16 3
```

`MAP 地图` 随机传送；酷明语料使用的 `MAP 地图 X Y [范围]` 与 `MAPMOVE` 共用同一真实传送接缝。范围为 0 时定点传送，大于 0 时只在有效可行走格中选点。

## 字符串列表位置

```text
#ACT
GETSTRINGPOS ..\QuestDiary\命格名称.txt 破军
```

`GETSTRINGPOS` 只读取当前已发布候选快照中的安全逻辑路径，按大小写不敏感的整行精确匹配查找，并把零基行号写入 `N0`；未命中写入 `9999999`。第三参数为 `1` 的绝对路径模式不会访问宿主文件系统，同样返回未命中值，避免脚本越过内容根读取任意文件。

## 已知差异与排错

- 这些命令使用结构化失败并保持旧值，不静默接受非法数值。
- HP/MP 的双边界都比较当前值，不读取最大 HP/MP。
- 命令执行仍位于服务端主线程；脚本热重载只替换后续调用使用的快照。
- 参数错误日志以 `[TxtScripts]` 开头并包含当前页码。

## 物品检测、给予与回收

物品扩展语法只在 `TxtScriptsCompatibilityVersion` 以 `LFM2-` 开头时启用，避免改变既有 Crystal `CHECKITEM` 的第三参数含义。

```text
#IF
CHECKITEM 麻痹 1 1 0
#ACT
GIVE 回城卷 2
TAKE 麻痹 1 0 1 1 -1
```

`CHECKITEM` 的第三参数 `1` 表示部分名称匹配，第四参数表示是否包含同源改名装备。当前物品模型没有自定义改名字段，因此 `0/1` 都按数据库原名计数；如果以后引入实例改名，必须再补精确分流。`TAKE` 依次传入物品名、数量、改名检测、部分匹配、排除自定义 OK 框和持久模式；当前适配要求改名检测为 `0`、排除自定义 OK 框为 `1`。持久模式 `0` 不过滤、`-1` 只取满持久、`-2` 只取未满持久。回收前先核对总数，数量不足不会删除一部分物品。

基础 `GIVE 物品名 数量` 映射到现有 `GIVEITEM`。翎风扩展 `GIVE` 的极品位置、刺术、箭术、武力和特殊持久参数没有稳定的 LyoCrystal 等价字段，候选快照会失败关闭；迁移时改为基础 `GIVEITEM`，或由类型化 C# 物品 API 明确构造项目实际支持的属性。

既有 `GIVEITEM 物品名 数量` 与 `TAKEITEM 物品名 数量 [最低持久]` 保持 Crystal 行为，用于不需要部分名称、改名装备或自定义 OK 框的脚本。

`GIVESTATEITEM 物品名 禁扔 禁交易 禁存 禁修 禁售 禁爆 丢弃消失 [数量]` 发放带单件限制状态的物品。七个状态参数只接受 `0` 或 `1`，数量省略时为 `1`。限制写入物品实例并随二进制及 SQL 存档保存，不修改同名物品的数据库模板；状态不同的可叠加物品不会合并。服务端在丢弃、交易、仓库、修理、出售和死亡掉落入口执行限制，PC 客户端同步显示对应提示。

`SETITEMSTATE 装备位置 项目 0|1` 设置单件物品限制，项目 `0..7` 依次为禁止扔、交易、存、修、售、爆、丢弃消失和禁止取下；`CHECKITEMSTATE 装备位置 项目` 读取同一有效状态。三参数 `SETITEMSTATE 装备位置 0|1` 兼容旧 `SetItemBind`，把物品绑定或解绑当前人物；`CHECKITEMBIND 装备位置` 检测该物品是否已经人物绑定。项目 7 使用独立持久字段并在真实 PC/英雄脱装备入口阻断，不能由客户端移动包绕过。

`SETCUSTOMITEMABIL 装备位置 属性位置 属性类型 属性值` 与 `GETCUSTOMITEMABIL 装备位置 属性位置 属性类型 结果变量` 读写同一件装备的自定义属性元数据。属性类型 `0..4` 分别为颜色、绑定属性、显示顺序、显示模式和模块；结果可写入数字或字符串变量。读取使用真实物品实例，不按名称猜测；装备、属性位置或字段无效时不改结果变量。英雄写法使用对应的 `H.` 前缀。

`LINKGIVEITEM` 把当前动作段最近一次由 `GIVESTATEITEM` 成功放入背包的真实实例绑定为位置 `-1`。随后 `SETITEMEFFECT -1 ...`、`SETITEMFROM -1 ...`、`UPDATEITEM -1` 等实例命令都操作该对象；`CLEARLINKITEM` 解除绑定，且同段后续 `-1` 不会重新落回外层拾取或双击触发物品。没有成功发放实例时绑定失败并记录诊断，不会复制、删除或猜测其他物品。

`SETICON 位置 资源包 图片 X Y 帧数 效果 层级 速度 [仅自己可见]` 保留酷明人物顶戴图标参数；`SETICON 位置 -1` 用于清除。当前 E1 只保证脚本可严格解析且不误写服务端 Buff；顶戴资源、角色附着渲染和同步协议属于 `LingFeng/OverheadIcon` E2 客户端契约，未提供时不得宣称客户端已经显示。

`TAKEBAGITEM 物品名1|物品名2 数量 元宝 金币 泡点 经验 结果变量 聚灵珠 [提示] [颜色] [极品] [改名] [等级]` 从真实背包按清单与可选颜色回收至多指定数量，把实际数量写入变量，并按实际数量结算金币和经验。奖励乘积先检查溢出；元宝、泡点、聚灵珠经验以及非零极品/改名/等级筛选尚需 `LingFeng/BagRecycleExtendedRewards` E2 适配器，缺失时会在删除任何物品之前失败关闭。

`TAKEW 物品名称 [数量]` 按物品数据库显示名称从人物已穿戴装备及其内嵌槽位直接销毁物品。执行前会原子检查总数量；不足时不删除任何物品，成功后统一刷新装备包与人物属性。该命令不等同于 `UNEQUIPITEM`，不会把装备移回背包。

`CHECKACCOUNTLIST 名单路径`、`ADDACCOUNTLIST 名单路径` 与 `DELACCOUNTLIST 名单路径` 按登录 `AccountID` 检测、登记和删除，不使用可重名或可改名的角色名。路径必须能归一化到候选内的安全 TXT 逻辑键，运行数据写入隔离的账号名单存储而不改原始 `QuestDiary`；路径或账号无效时检测按“已存在”失败关闭，写入失败会终止当前动作段，避免后续限次奖励在名单未保存时继续发放。指向候选外通区充值目录的历史路径不会直接访问宿主文件系统，而会登记 `LingFeng/ExternalAccountList` E2 依赖，只有显式提供受托管外部名单适配器后才允许整服发布。

`CHECKNAMEDATETIMELIST 名单路径 清理过期 到期变量 剩余日 剩余时 剩余分` 与 `ADDNAMEDATETIMELIST 名单路径 天 小时 分钟` 按安全逻辑路径隔离当前人物的时效资格。续期以尚未到期的旧时间为基线，否则以当前时间为基线；检测输出分钟精度的到期时间与剩余日时分。运行状态随人物进度持久化且不修改只读 `QuestDiary` 文件；翎风外部名单中的历史人物导入属于 `LingFeng/TimedNameListImport` E2 依赖。

`L.RANGEHARM X Y 范围 伤害 效果 效果值 抗性检查 目标 [WIL 起图 张数 速度 透明 物理]` 中的 `L.` 表示当前伤害来源，而不是当前执行脚本的人物。酷明实际使用的效果 `0`（无附加状态）和 `8`（冰冻）已接入真实受击、死亡归属、抗性和地图特效链；目标 `0/1/2` 分别表示全部、人物、怪物，并继续服从安全区和可攻击关系。其他附加效果编号尚未接入时会在造成任何伤害前失败关闭。

`CHANGEITEMUPGRADECOUNT 位置 +|-|= 星数` 与 `H.CHANGEITEMUPGRADECOUNT` 分别调整人物和英雄装备实例的升级星数，并发送真实 `RefreshItem`；结果必须保持在 `0..255`，否则不修改也不发送刷新。`CHECKUPGRADECOUNT 位置 比较符 星数` 与英雄别名检测同一字段。酷明使用的位置 `3` 对应项链，且动态 `U` 变量在真实 NPC 上下文解析；人物位置 `-1` 可操作已关联物品。旧自定义版本物品读取为 0，新版本保存、克隆和 SQL 自定义状态往返均保留星数。升级框、OK 框、首饰盒及生肖盒等扩展位置尚未接入时严格拒绝。

`CLOSEARRBUFF 按钮序号` 与 `SETARRBUFF` 共用自动排列按钮客户端契约。E1 会解析并保留酷明药剂系统使用的动态按钮序号表达式，但不会把客户端按钮误当成服务端 Buff 清除；按钮关闭、点击及到期回调只有在 E2 提供 `LingFeng/AutoArrangedBuff` 客户端契约后才可声明可见生效。

`SCATTERMONITEMS 怪物名称 [地图 X Y]` 直接调用该怪物已经发布的真实掉落表，不创建或击杀一个假怪物。省略地图时以人物当前位置为中心；提供地图与坐标时先完整验证地图、坐标和怪物，再生成带人物拾取归属的地面物品，并继续经过现有掉落倍率、条件、稀有公告及 Hook 链。

`ADDARRBUTTON 分组 触发 资源包 默认图 经过图 按下图 位置 标题 说明` 与 `DELARRBUTTON 按钮编号` 属于客户端自动排列按钮协议。E1 完整保留封神脚本的标题转义、动态文本和说明参数，但不会伪造不可点击的服务端状态；资源显示及 `[@ArrButtonClickX]` 回调由 E2 的 `LingFeng/AutoArrangedButton` 契约门禁负责。

`DELBOXITEM OK框编号 [数量]` 必须依赖真实自定义 OK 框托管会话。E1 在缺少 `LingFeng/CustomItemBox` 契约时保留语法但终止当前整个动作段：既不猜测背包物品并删除，也不允许后续升级或奖励继续执行，从而避免材料未扣却获得结果。

`CHECKACTIVEFENGHAO 称号名称` 与 `H.CHECKACTIVEFENGHAO` 检测人物或英雄当前真正激活的称号，不等同于“曾经拥有该称号”。它读取与 `GIVEFENGHAO ... 1`、`RECYCFENGHAO` 共用的持久进度；称号被回收后激活状态同步失效。

`OPENSTORAGEVIEW 0 [X Y]` 复用现有 `UserStorage + NPCStorage` 协议打开普通可视仓库；坐标参数在当前客户端协议没有对应字段，因此只保留而不伪造位置。模式 `1` 的无限仓库需要独立持久层，当前会在打开及后续动作前失败关闭，不能降级到普通仓库冒充。

`PLAYEFFECT`、`M.PLAYEFFECT` 与 `PET.PLAYEFFECT` 分别把特效锚定到人物、当前真实怪物目标和首个存活宠物。协议携带对象 ID、像素偏移、资源包、起图、帧数、循环、速度、图层及普通/混合绘制方式；客户端随对象移动绘制，`*` 偏移按 0 处理。酷明命格使用 `M.`，封神法宝使用 `PET.`，两套验证对象不混用。

`CHECKSLAVECOUNT 比较符 数量 [宝宝名称 是否检查名称数字]` 只统计当前人物仍存活的真实宝宝。名称省略时统计全部；末参数为 `0` 时忽略名称末尾连续数字，例如 `骷髅1`、`骷髅2` 均匹配 `骷髅`，为 `1` 时按完整名称比较。酷明命格脚本使用的 `骷髅`、`变异骷髅` 与 `神兽` 检测均走同一人物宝宝集合。

`ADDMIRRORMAP 源地图 镜像编号 标题 秒数 返回地图 小地图 结果变量 显示模式 返回X,返回Y` 创建独立运行时地图；`CHECKMIRRORMAP`、`SETMIRRORMAPTIME`、`GETMIRRORMAPTIME` 与 `DELMIRRORMAP` 共用同一生命周期。镜像复制源地图静态格子但不共享格子对象，脚本中的 `<$MAP>` 使用镜像编号，客户端仍加载源地图物理文件。创建前完整验证源图、返回图、坐标、时间和唯一编号；删除或到期必须先把人物送回指定地图，回送失败时保留镜像并下一秒重试，不删除人物仍在使用的地图。

`ADDTEXTLIST 文件位置 内容 [是否绝对路径]` 把完整内容登记到安全逻辑路径对应的运行期增量名单，重复内容保持单条。原始 `QuestDiary` 候选始终只读；增量以 UTF-8 JSON 原子写入 `Configs/LingFengRuntime/TextLists`，重启后由 `CHECKTEXTLIST` 与当前已发布候选合并读取。绝对路径标志为 `1`、路径越界、内容为空或持久化失败时终止当前动作段，避免周印、账号领奖等限次状态未落盘却继续发奖。

`CHECKCACHETEXTLIST` 是 `CHECKTEXTLIST` 的翎风缓存别名，两者都从已发布文本快照与安全运行期增量合并读取，不在命令执行期重新打开任意磁盘路径。

`#Define $(名称) 值` 在翎风物理候选发布前统一展开，包含命令名位置，例如 `Check$(货币元宝变量)` 可展开为 `CheckGameGold`。同名同值定义幂等；同名异值、循环引用、超过 16 层或展开后单行超过 64 KiB 时拒绝整个候选。定义行转为注释并保留原始源行号，运行时与严格预检始终读取同一展开快照。`CHECKGAMEGOLD ? 数量` 的问号按“元宝余额至少达到数量”处理。

`SETSKILLPOWER 技能ID =|+|- 人物伤害% 人物固定伤害 怪物伤害% 怪物固定伤害 防御% 固定防御 时间秒 是否保存` 为指定技能设置六维修正。数值范围为 `-32768..32767`，时间 `0` 表示一直有效，保存参数只接受 `0/1`。持久值保存在人物脚本变量中；不保存的定时覆盖到期时会在同一次伤害计算中恢复下层持久值，不会留下一次攻击的空档。

`WHILE 变量或值 比较符 变量或值` 与 `ENDWHILE` 必须成对写在同一 `#ACT/#ELSEACT` 动作段内，支持 `= == != <> > >= < <=`。循环每轮重新读取变量，可嵌套；单次动作段最多执行 10000 轮，超出后终止当前动作段并记录 `TXT-RUNTIME-001`。缺失配对或参数非法会在严格候选发布前拒绝。

`ADDHUMNEWVALUE 属性编号 +|-|= 值 [时间秒] [酷明扩展0]` 增加人物隐藏元素属性。时间省略或为 `0` 时在线期间持续有效；同一脚本动作重触发只替换或刷新自身，不同脚本来源独立汇总和计时。例如一个来源增加 30 秒、另一个来源增加 10 秒，10 秒来源到期后只移除自身，仍保留 30 秒来源。装备、数据库和其他长期属性始终作为下层基线，不会被临时效果到期重置。当前已接入酷明实际使用的攻击增伤、物理/魔法减伤、忽视防御、反伤、生命/魔法百分比、抗麻痹/毒/冰冻/蛛网、致命与致命防御等战斗链；尚未完整接入的编号维持兼容等级 C，不冒充完整翎风实现。

`CHANGEHUMABILITY` 与 `CHANGEHUMABILITYPERCENTAGE` 不直接改写人物基础、装备或数据库属性，而是写入按脚本动作区分的运行时属性层。同一动作再次触发只刷新自己的值和期限；不同动作产生的永久层、30 秒层和 10 秒层同时存在。10 秒层到期时只删除自身，重新计算结果仍包含基础属性、永久层和剩余的 30 秒层。

`CHANGESPEED`、`M.CHANGESPEED` 和 `FS.CHANGESPEED` 分别作用于当前人物、当前事件目标、人物当前存活分身。`FS.` 是翎风“分身”前缀，不是属性刷新或永久属性缩写。三种目标都使用按脚本动作区分的速度来源层；无时限层、30 秒层和 10 秒层可同时存在，较短层到期只移除自身。酷明属性刷新脚本中人物与分身的同值命令因此不会互相叠加到同一对象。

`CLEARDELAYGOTO` 不带参数时清除人物尚未执行的普通 `DELAYGOTO` 导航；`CLEARDELAYGOTO 1` 按翎风帮助定义只清除 `SENDCENTERMSG`/`SENDDELAYMSG` 倒计时，不会误清普通脚本跳转。酷明回城石使用的是参数 `1`。

`CLOSECLIENTBUFF 编号` 在 E1 保留完整编号且不删除服务端真实属性。酷明秘境脚本使用编号 `310`，超过旧 `RemoveBuff` 的单字节编号范围，因此在专用宽编号客户端协议完成前不会错误截断发送；该可视关闭效果列入 E2。命格状态到期页的 `@CloseClientBuff181..187` 属于回调标签，并非该动作命令。

`<$CURRRTARGETNAME>.SETARRBUFF` 与人物 `SETARRBUFF` 共享 `LingFeng/AutoArrangedBuff` 客户端契约。E1 完整保存当前目标前缀及动态参数，但不会把目标图标误写成执行者的服务端 Buff；自动排列、显示、点击和到期回调仍由 E2 契约失败关闭。该命令只纳入整服语法兼容，不作为酷明玩法验收证据；酷明玩法仍只验证原版命格。

`SETSNDACASKET 0|1` 与 `ACTIVATIONCASKET` 分别表示首饰盒图标灰显/彩色及激活。E1 严格保留官方参数，但在 `LingFeng/JewelryCasket` 客户端契约完成前不伪造人物状态。`UNALLOWITEMINTOBOX` 与 `RETURNBOXITEM 位置` 属于自定义 OK 框物品事务；没有可信 `LingFeng/CustomItemBox` 会话和物品身份时会立即停止当前动作段，避免后续升级或奖励落到错误物品。这组命令只作整服语法与安全边界验证，不作为酷明玩法证据；酷明玩法继续仅使用命格。

`ADDBUTTON` 在 E1 至少校验并保留资源包、按钮序号、三态图片、坐标、挂载位置和标题；实际绘制及 `[@ButtonClickX]` 回调由 `LingFeng/CustomButton` 客户端契约在 E2 失败关闭。`SETNEWITEMVALUEEX 装备位置 属性 运算 数值 秒数` 已接入人物临时隐藏属性来源层：每个脚本动作拥有独立来源键，因此 10 秒效果到期只移除自身，仍保留 30 秒效果以及长期属性；同一动作重放只刷新自身，不会重复叠加。属性 12 属于装备死亡防爆语义，等待死亡掉落领域接入后再声明完整支持。

`SETUPGRADEITEM 位置` 可接受 `0..13` 装备位置或 `BoxItem0..31`，E1 保留其后续物品操作上下文标记；在自定义框会话尚未托管前不会缓存不可信物品引用。`OPENITEMBOXEX 编号 0|1 提示` 校验并保留旧拆解框参数，但 `S0/N0` 写入、`[@GetBoxItemX]` 触发和自动回收必须等 `LingFeng/LegacyItemBox` 客户端事务完成，避免伪造一次成功的物品放入。

`CHANGEITEMNAME 位置 名称` 在 E1 保留最多 60 字符的实例名称，但不会修改共享 `ItemInfo`，避免同模板的全部物品一起改名；实例字段、持久化及富文本显示由 `LingFeng/ItemInstanceName` 在 E2 接入。`SETBODYCOLOR 颜色 秒数 [类型]` 保留固定色或变色参数，但人体染色不等于名称颜色，因此不会错误复用旧 `ColourChanged.NameColour`；专用 `LingFeng/BodyColor` 客户端协议完成前失败关闭。

外部事务组 `SETBIGSTORAGECOUNT`、`OPENAUTOPICKITEM`、`CLOSEAUTOPICKITEM`、`BREAKADDSELLPLAYER`、`STOPBUYUSER`、`STOPTAKEON`、`STOPTAKEOFF`、`AUTOTAKEONITEM`、`TAKEPOSW`、`SETITEMFROM` 和 `CHANGEHUMNAME` 只在 E1 校验并保留参数。无限仓库、自动拾取、玩家交易、装备原子事务、物品来源和角色改名都必须由各自 E2 领域契约完成；缺少契约时不修改人物、物品或数据库，也不返回假的成功状态。

跨目标和玩法组 `HCALL`、`ADDATTACKSABUKALL`、`CREATEMYSHOP`、`CHECKMYSHOP`、`CHECKSHOPNAME`、`SETOFFLINEPLAY`、`STARTAUTOPLAYGAME`、`STOPAUTOPLAYGAME`、`PLAYSOUNDEXT` 与 `SETRANKLEVELNAME` 同样维持 C 级。动作保留完整目标、页面、攻城、商店、挂机、音频或称号参数；两个商店检测在领域适配前固定失败关闭，避免脚本在个人商店尚未建立时继续发货或扣款。

封神精简包使用的 `CHECKBOXITEMCOUNT 编号` 与 `SENDMOVEHINTMSG 消息 前景色 背景色 [X Y 时长 模式]` 已进入相同 E1 边界。前者在没有可信物品框会话时为假，后者只保留短格式或完整格式参数；专用物品框和移动提示客户端契约完成前不冒充成功。精简包缺少的 `Constant.Ini` 作为 `LingFeng/ExternalInclude/Constant.Ini` E2 依赖登记，不生成假的常量文件。

酷明命格伤害页中的 `<$CURRRTARGETNAME>.FORMULATION`、`<$CURRRTARGETNAME>.CHANGEHUMABILITY` 与 `<$CURRRTARGETNAME>.TAKE` 均以本次伤害事件锁定的真实人物为目标。公式中的 `<$MAXAC>`、`<$MAXMAC>` 等人物常量读取目标快照，结果写回施法脚本变量；写入整数变量时按翎风语义向零截断。临时减防继续使用独立来源层，短效果到期不会清除较长效果或长期属性；金币扣除只动目标账户，余额不足时整笔失败。

`<$CURRRTARGETNAME>.GOTO @页面` 与 `<$CURRRTARGETNAME>.DELAYGOTO 毫秒 @页面` 把同一 Called 脚本中的页面调度给伤害事件锁定的目标人物；后者单位为毫秒，酷明的 `7000` 即 7 秒。目标页通过隔离的系统调用执行，不覆盖目标正在进行的 NPC 会话。为防止恶意堆积，延迟最多 24 小时且每个人物最多保留 64 条目标页任务；即时 `GOTO` 在目标人物下一处理点执行，而不是在施法者调用栈内同步递归。

酷明狂暴死亡页动态展开后的 `<$KILLER>.GAMEGIRD` 与 `<$KILLER>.GAMEGOLD` 只调整本次真实人物击杀者的灵符和元宝账本，不会奖励死亡脚本的执行人物。`GAMEGOLD` 继续沿用当前项目对应 `PearlCount` 的既有语义；缺少人物击杀者上下文、下溢或越界时整条命令失败关闭。

`M.CHANGEHUMABILITY` 与 `M.CHANGEHUMABILITYPERCENTAGE` 把固定值或百分比临时修正施加到当前事件怪物，并与人物临时属性使用同一独立来源和到期聚合模型。`L.GETOBJECTABILITYEX` 与 `L.MAKEPOSION` 的 `L.` 表示本次真实攻击来源；优先按伤害事件对象 ID 锁定玩家、英雄或宝宝，名称只作为旧事件的玩家回退。命格反制毒、麻痹和攻击力读取不会因同名对象命中错误目标。

死亡触发条件 `KILLBYHUM` 是 `CHECKKILLBYHUM` 的翎风兼容写法，两者都只读取当前死亡事件的真实击杀者；玩家击杀为真，怪物击杀为假，不接受参数。

`CHECKMAPMONCOUNT 地图 比较符 数量 [排除宝宝]` 统计指定地图上的存活怪物。末参数为 `1` 时排除人物与英雄宝宝，为 `0` 或省略时计入；地图不存在或参数无效时条件失败关闭。

`GETMAPMONCOUNT 地图 排除宝宝 结果变量` 使用同一份存活怪物计数规则，并把结果写入脚本变量。排除宝宝为 `1` 时不计人物与英雄宝宝，为 `0` 时计入；地图或结果变量无效时失败关闭。

`CHECKUSEITEM 位置` 检测人物装备，`H.CHECKUSEITEM 位置` 检测当前出战英雄装备。当前映射翎风位置 `0` 至 `13`；英雄未出战、位置无效或该栏为空时条件为假。

`CHANGEJOB Warrior|Wizard|Taoist` 复用人物职业切换动作。它只变更职业；酷明原脚本中的 `CLEARSKILL` 与各职业 `ADDSKILL` 仍分别负责清理和重建技能，避免引擎暗中添加脚本未声明的技能。

`CLEARSKILL` 删除当前人物全部技能，并按技能表倒序发送移除同步，避免删除过程中位置编号漂移。当前不接受参数；英雄 `H.` 前缀留待英雄技能协议阶段接入。

`SETHUMATTACKMODE 模式 秒数 [地图|*]` 在指定期限强制人物攻击模式。首次执行保存进入前模式，重触发只更新强制值和到期时间，不把临时值覆盖为恢复基线；到期或离开限定地图后恢复并发送 `ChangeAMode`。强制期客户端手动切换会被拒绝。当前领域枚举支持 `0` 至 `5`，酷明神秘战场使用的 `5` 为全体模式。

`CHECKSTORAGEOPEN 2|3|4` 检测账户对应仓库页是否已永久开放；`OPENSTORATGE 页 1` 永久开放第 2 至 4 页并发送现有 `ResizeStorage`。开放状态以账户存储数组长度和扩仓状态共同判定，随既有二进制与 SQL 账户仓库快照持久化；不接受关闭参数，避免删除已有页内物品。

`RENEWLEVEL 转次数 转后等级 分配点数` 将转生次数与未分配属性点写入人物持久账本。转后等级为 `0` 时保持当前等级；非零时复用现有等级刷新及升级事件。三个结果在写入前统一检查边界，任一溢出则整条命令不生效。酷明实际使用 `1 0 奖励点数`，其后天赋补点仍由原脚本独立结算。

`KILLSLAVE 清尸 [宝宝名称|*]` 让当前人物的匹配宝宝进入真实死亡链。清尸为 `1` 时同一动作立即从地图和主人宝宝集合移除尸体，为 `0` 时保留现有死亡延时；名称省略或为 `*` 时处理全部人物宝宝，不混入英雄宝宝。

`CHECKUNDERWAR 城堡名称` 按城堡名称检查当前 `WarIsOn` 状态，名称大小写不敏感。它检测的是指定城堡是否正在攻城，不依赖人物所在地图或行会。

`CHECKPOSEDIR [1|2]` 要求人物与面前相邻格的活着人物互相面对；`1` 额外要求同性，`2` 要求异性，省略时不限性别。`CHECKPOSELEVEL =|>|< 等级` 检测面前相邻格人物的等级，它本身不要求对方朝向。

`ISCASTLEGUILD` 检测当前人物行会是否拥有任一城堡。`ISCASTLEMASTER` 还要求人物为该行会首席等级，不把普通沙城成员误判为城主。

`HAVEMASTER` 只读取人物持久师徒关系；`Mentor` 为非零人物索引时通过，不要求对方当前在线。

`CHECKREPAIRALLGOLD 数值变量` 按每件装备当前耐久修复价的三倍统计全身特修总价，先写回变量，再以人物金币判断条件结果；`REPAIRALL` 与翎风别名 `ACTREPAIRALL` 执行同一个全身特修动作，只恢复允许特修的已穿戴装备，`NoSRepair` 等保护物品既不计价也不修复。

`KILLMONEXPRATE 倍率 秒数 [保存] [静默]` 的倍率除以 `100` 后作用于真实 `GainExp`，秒数 `0` 表示永久。每个脚本动作是独立来源：10 秒层到期只移除自身，不会清掉 30 秒层或永久命格经验属性。保存为 `1` 时记录绝对到期时间，重登只恢复剩余时间；静默为 `1` 时不发送系统提示。当前安全范围为 `100` 至 `1000000`。

`RECALCMONABILITY 地图|SELF 怪物|* [X Y 范围]` 对匹配的存活怪物重新执行完整属性计算，使已有 `CHANGEMONABILITY` 来源层重新反映到当前属性。省略坐标时处理全图；给出坐标但范围为 `0` 时只匹配该坐标；范围大于 `0` 时按半径筛选。目标按对象编号稳定排序，单次最多处理 2048 个，防止全图脚本无界阻塞。

`MONDROPITEMSEX 怪物名称 物品名称 数量 中心模式` 强制生成真实地面物品：中心模式 `0` 以人物为中心，`1` 在 `@KILLMON` 中以被击杀怪物坐标为中心。物品保留人物归属时间、稀有掉落提示并在完成后聚合派发一次 `@M2DROPITEM`；它按官方语义不受普通爆率限制，单次最多生成 1000 件。怪物、物品或事件地图坐标无效时整条命令失败关闭。

`SETREBORN 复活次数 有效秒数` 在人物在线状态中授予限时原地复活，不受复活戒指五分钟间隔控制。每次真实死亡先扣一次次数、恢复满体力，再派发 QFunction 的 `[@NpcRevival]`；触发页可用 `<$NpcRebornCount>` 读取剩余次数，用 `<$TriggerNpcRebornCount>` 读取本轮命令已使用次数。次数为 `0` 会立即清除状态，次数耗尽或有效期结束后继续执行原项目正常死亡、掉落和死亡脚本。封神法宝的 `SETREBORN <$Str(N$复活次数)> 60000` 已走真实死亡链验证。

`SENDCENTERMSG 前景色 背景色 文本 模式 时间` 当前会以现有 `Announcement` 消息提供可读降级；`M.SENDCENTERMSG` 把消息只发给当前事件锁定的人物目标，命格伤害事件已验证不会误发给脚本执行者。E1 保留受众边界但不伪造翎风居中布局、颜色、倒计时替换或到期标签回调，这些能力继续由 E2 客户端协议门禁负责。

`FILTERGLOBALMSG 类型 0|1` 是当前人物自己的消息过滤设置，不会修改其他在线人物。类型 `1` 会过滤发给该人物的全服 `SENDCENTERMSG`，类型 `3` 会过滤全服 `SENDMSG 0..3`；关闭后立即恢复接收。过滤位保存到人物脚本进度中，重登不会因一次脚本调用丢失。类型 `2` 的翎风专用掉落提示和类型 `4` 的专用滚动消息还没有可区分的客户端来源通道，当前保留参数但不宣称完全兼容。

`SENDMSG 0..3 文本` 按全服普通、喊话、系统、提示类型派发，并逐个尊重接收人物的类型 `3` 过滤；`SENDMSG 5..7 文本` 只发送给当前脚本人物。类型 `4`、`8` 以及翎风专用颜色和头顶布局等待客户端协议接入。

`SENDNEWLINEMSG 受众 前景色 背景色 字号 Y坐标 时长 绘制方式 文本 [范围 X坐标]` 当前按受众 `0..7` 路由到全服、自己、队伍、行会或当前地图人物，并正确处理是否包含自己。E1 以现有 `Announcement` 提供可读降级且保留 `{文字|前景:背景:模式}` 等富文本原文；多行绘制、颜色、字号、坐标、时长、淡入淡出及图片数字仍由 E2 客户端协议门禁负责。

`TAKEBAGITEMEX IDX范围 数量 元宝 金币 泡点 经验 结果变量 聚灵珠 [提示 颜色 极品 改名 等级]` 按物品数据库 IDX 回收真实背包实例，编号支持 `712-718`、竖线组合及单值。酷明异兽孵化使用的零奖励形式会写入实际回收数量，并保持范围外物品不动；非零奖励账本或尚无完整实例接缝的非零极品、改名、等级筛选会在删除任何物品前失败关闭。

`CHANGEMAPDESC 新显示名 是否保存` 修改当前地图实例的客户端显示标题，并立即刷新同图人物。保存参数 `0` 使用独立运行时覆盖，不改数据库中的原始地图标题，停服重启后自然恢复；保存参数 `1` 尚未接入地图配置持久事务，会在修改前失败关闭。

`SENDDELAYMSG 文本 秒数 字体颜色 换图是否取消 @标签 [X坐标]` 为当前人物登记一次延迟脚本任务。时间到达后仍回到发起命令的原脚本执行目标标签，不读取或覆盖人物当时正在进行的 NPC 会话；换图取消为 `1` 时，人物离开原地图后不再触发。当前客户端没有翎风专用逐秒大字协议，文本会先以中心公告显示，字体颜色、逐秒替换 `%s` 和 X 坐标等待客户端契约补齐。

`POWERRATE 倍率 秒数 [保存] [静默] [目标类型]` 把当前人物及其英雄的攻击伤害按百分比结算；目标类型 `0` 为全部、`1` 为人物、`2` 为怪物。`SETBLASTHITRATE 倍率 秒数` 作用于暴击结算结果，`120` 表示 `1.2` 倍。`KILLMONBURSTRATE 倍率 [秒数] [保存] [静默]` 在怪物掉落链中调整基础爆率。三类倍率都按“脚本来源”独立保存与到期：永久层、30 秒层和 10 秒层可以同时存在，10 秒层结束只撤销自己的贡献，不会重置 30 秒层或人物长期属性；同一脚本动作再次执行则只刷新该动作自身。保存参数只适用于攻击与杀怪爆率，记录绝对到期时间并在重登时恢复剩余时间。

`SETSLAVEATTACKHUMPOWERRATE 宝宝名称 倍率` 设置当前人物指定宝宝或分身对人物、英雄与假人的伤害倍率，数值除以 `100` 后生效；`0` 同时阻止其选择人物目标。命格分身可以按 `<$USERNAME>` 匹配，普通宝宝也可按数据库名或显示名匹配。该倍率不影响攻击怪物。

`RECALLSELF 秒数 数量 属性百分比 [身体颜色 衣服外观 武器外观 X Y]` 以服务器 `CloneName` 怪物定义召唤当前人物分身，按召唤瞬间人物属性快照继承并在期限结束后死亡清理；`0 0` 坐标表示人物当前位置。当前 E1 支持酷明命格实际使用的零外观参数，非零身体、衣服或武器外观因客户端没有对应分身协议而失败关闭，不生成半成品分身。

`CHANGEMODEEX 模式 秒数 [附加值]` 当前接入酷明实际使用的模式 `1`（临时无敌）与 `2`（临时隐身）。同一模式再次执行时以最后一次时长重计时，秒数 `0` 立即解除；临时无敌与管理无敌分别保存，结束时不会关闭管理员状态。模式 `3` 至 `14` 尚未映射时失败关闭。

`TAKE 物品 数量 [改名检测 名称匹配 排除自定义框 持久模式]` 的短格式默认只扫描人物背包并排除当前项目不存在的自定义 OK 框，因此酷明异兽的 `TAKE 名称 1 1` 可原子扣除普通背包物品。当前物品模型没有独立改名字段，改名检测为 `1` 时仍按数据库原始名匹配；显式要求包含自定义框时失败关闭。

`GETDBIDXITEMFIELDVALUE 物品IDX NAME 结果变量` 按物品数据库索引读取显示名称并写入脚本变量，覆盖酷明异兽融合遍历背包 IDX 后生成可回收名称列表的用法；未知 IDX、其他字段或无效变量失败关闭。

`GETBAGINFO ItemCount 结果变量 [StdMode|...]` 统计背包格中的物品实例数，不按叠加数量放大；`ItemMakeIndex`、`ItemIdx`、`ItemName` 分别把实例唯一号、数据库索引和数据库显示名写入 `L$` 列表。可选 StdMode 列表按物品类型过滤。结果列表按背包槽位顺序稳定生成，整次替换旧列表；变量类型、类型编号或上下文无效时不写入半份结果。

`CHECKMAPHUMANCOUNT 地图 比较符 数量` 按逻辑地图名或物理地图名统计存活人物，支持 `< > = == <= >=`。`CHECKMONMAP 地图 最低数量 [排除宝宝]` 判断存活怪物数是否达到阈值，末参数为 `1` 时排除人物与英雄宝宝。两者都只读当前主线程快照，地图不存在时为假。

`CHECKPOSEMARRY`、`CHECKPOSEGENDER MAN|男|WOMAN|女` 与 `CHECKPOSEMASTER` 检测当前人物正前方相邻格的活着人物；性别、婚姻和师徒关系直接读取持久领域字段，不要求对方反向面对。`CHECKMASTER` 检测自己已有师徒关系，`CHECKISMASTER` 检测自己是否为师傅身份。

`CHECKRANGEHUMCOUNT 地图 X Y 范围 比较符 数量` 统计指定范围内的存活人物；地图为 `SELF` 时使用当前地图，X/Y 同为 `0` 时使用人物当前位置。范围判断复用服务器地图距离规则，当前人物本身也按真实位置参与统计。

`TEXTREPLACE 原文 搜索文本 新文本 结果变量 区分大小写 只替换一次` 支持大小写敏感或不敏感、首个或全部替换，并把完整结果原子写入变量。`UNIXTOSTR Unix秒 结果变量 0|1` 按 UTC 输出 `yyyy-MM-dd HH:mm:ss` 或斜线日期格式；酷明脚本若需北京时间，继续按原脚本在转换前加 `28800` 秒。

`SETSTRINGBLANK 字符串变量 目标字节长度 0|1` 按 CP936 宽度把变量补齐到目标长度，方向 `0` 为前补、`1` 为后补；已经达到目标长度时不截断。旧帮助页记录上限 100，但 53 根参考语料中存在 110 至 170 的有效生产调用，因此当前兼容快照接受 `1..1024`，超过硬上限则在候选发布前拒绝，避免不受限扩张。

`GETSTRINGPOSEX 文件 搜索文本 行号变量 整行变量 绝对路径标志 [完全匹配]` 在 `#IF` 中返回是否命中，也可在 `#ACT` 中直接填充结果。它只读取当前已发布候选，按大小写不敏感的包含或整行匹配查找；动作模式未命中时写入 `9999999` 和空文本，绝对路径模式不访问宿主文件系统。

`SETONTIMER 定时器编号 间隔秒数 [执行次数]` 启动当前在线人物的个人定时器，编号范围 `0..255`；执行次数省略或为 `0` 时持续执行，正数表示执行指定次数后自动关闭。到期在人物主线程调用 `QManage.txt` 的 `[@OnTimer编号]`，同一编号再次启动会重置间隔与次数。`SETOFFTIMER 定时器编号` 立即关闭对应定时器。每个服务器循环对单个人物最多派发 256 个到期编号，延迟时不会补发积压轮次。

`LOOPGOTO @页面 [次数]` 同步执行当前脚本的目标页面；次数省略或为 `0` 时执行一次。目标页面内的 `ENDLOOP` 只终止当前最内层循环，嵌套循环共享单次调用最多 10000 轮的硬预算。目标标签缺失会在候选发布前拒绝，执行结束后恢复原 NPC 页面、延迟状态和检测缓存。

`GAMEGIRD +|-|= 数量` 调整当前人物独立持久化的灵符余额，允许范围为 `0..2147483647`，结果越界时拒绝且不动账。`CHECKGAMEGIRD ? 数量` 表示余额至少达到该数量，也支持 `< > = == <= >=`；`<$GAMEGIRD>` 显示同一余额。当前兼容层没有新增翎风原生背包货币 UI，脚本显示与账务闭环不依赖该 UI。

`GAMEPOINT +|-|= 数量`、`CHECKGAMEPOINT 比较符 数量` 与 `<$GAMEPOINT>` 共享当前人物独立持久化的游戏点账本。问号比较表示“余额至少达到目标”；减法下溢或结果超过 `2147483647` 时拒绝整次调整。该账本服务于泡点、骰子等脚本，不与元宝 `GAMEGOLD` 或灵符 `GAMEGIRD` 混用。

`GAMEDIAMOND +|-|= 数量`、`CHECKGAMEDIAMOND 比较符 数量` 与 `<$GAMEDIAMOND>` 共享当前人物独立持久化的金刚石账本，支持 `< > = == <= >=`；下溢或结果超过 `2147483647` 时拒绝整次调整且不动账。它不复用游戏点、元宝或灵符余额；当前兼容层没有新增翎风原生金刚石 UI，脚本检测、调整、显示与人物存档闭环不依赖该 UI。

`CHECKBINDMONEY 货币名称 数量` 与 `DECBINDMONEY 货币名称 数量` 当前把可证明的“铜钱”和“金币”映射到人物账户金币，检测与扣除使用同一余额；余额不足时不扣半笔，并发送既有 `LoseGold` 同步。项目尚无翎风自定义货币分组 Provider，其他货币名称会失败关闭，绝不自动冒充金币、元宝或信用点。酷明玩法验收仍只使用命格；本命令使用独立通用账务用例验证。

`LINKPICKUPITEM` 把当前 `@PICKUPITEMEX` 真实拾取事件中刚进入背包的物品绑定为 `-1`，后续可用 `SETITEMEFFECT`、`CHANGEITEMUPGRADECOUNT`、`UPDATEITEM -1` 等实例命令处理。绑定使用入包后的精确背包槽位，不按名称猜测同名物品；金币拾取、无有效槽位或离开拾取事件作用域时失败关闭。

`MARRY`、`MARRY REQUESTMARRY` 发起当前人物对面对面对象的既有求婚请求；`MARRY RESPONSEMARRY OK|FAIL` 接受或拒绝请求。`UNMARRY`、`UNMARRY REQUESTUNMARRY` 发起协议离婚，`UNMARRY RESPONSEUNMARRY` 接受；`UNMARRY REQUESTUNMARRY FORCE` 强制解除当前双方关系。所有写法复用服务器既有婚姻持久化、婚戒解绑、PC/移动端请求包和 `LoverUpdate` 刷新，不维护第二套婚姻状态。

`MASTER`、`MASTER REQUESTMASTER` 向正前方人物发起既有拜师请求；`MASTER RESPONSEMASTER OK|FAIL` 接受或拒绝。`UNMASTER`、`UNMASTER REQUESTUNMASTER`、`UNMASTER RESPONSEUNMASTER` 解除师徒关系，末尾 `FORCE` 使用领域强制解除。请求、双方身份、经验结算、冷却和 `MentorUpdate` 均复用现有服务器师徒链。

`CHANGEMONABILITY 地图 怪物 属性 +|-|= 值 值类型 [X Y 范围]` 修改匹配的存活怪物。地图可写 `SELF`，怪物可写 `*`；省略坐标时作用全图，范围为 `0` 时只作用坐标点。当前已覆盖酷明脱战脚本的点值属性 `0` 当前生命、`1` 最大生命、`8` 攻击下限、`9` 攻击上限；百分比、速度、移动间隔和有效时间设置尚未接入，遇到这些参数会失败关闭。

`CLEARITEMMAP 地图 [X Y 范围 [物品名称]]` 清理指定地图的真实地面物品。省略坐标时清理全图；名称省略或为 `*` 时清理全部物品，指定名称时只清理匹配物品。命令同时移除地图格、服务器全局对象和客户端对象，不会扫描或修改人物背包。

`CLEARMAPMON 地图` 让指定地图第一实例的存活野怪进入现有死亡链，并保留人物、英雄及其宝宝。酷明神秘战场和魔龙献宝可直接使用；当前项目没有翎风“禁止清除怪物名单”的独立配置模型，因此依赖该名单的版本会在后续 E2 阶段补齐。

`WRITECACHECONFIGFILEITEM INI路径 节名 键名 值` 更新已发布 Envir 候选中的 INI 内存缓存，随后可由 `READCACHECONFIGFILEITEM` 立即读取。普通 TXT 热重载不会冲掉运行期缓存；停服时按原文件的 UTF-8/CP936 编码与 CRLF/LF 换行原子保存，注释和未修改配置项保持不变。为避免脚本获得任意宿主文件写入能力，越过 Envir 根目录的路径失败关闭；酷明位于 Envir 内的 4 处骰子/命格配置写入已闭环，指向 `Mir通用配置` 的 3 处跨根共享配置保持 C 级并失败关闭。

`SKILLLEVEL 技能名 +|-|= 等级 [0|1]` 与 `CHECKSKILL 技能名 >|<|= 等级 [0|1]` 的末参数省略或为 `0` 时操作既有普通技能等级；为 `1` 时操作人物独立持久化的强化等级。强化等级目前供脚本读写与玩法分支使用，尚未接入技能伤害公式和翎风原生强化技能 UI，因此动作兼容等级为 C。

`MapInfo.txt` 的 `FB(容量,副本名称,模式,进入延长分钟[,空图回收秒])` 声明副本模板。模式 `0` 为战法道三职业组队、`1` 为普通组队、`2` 为个人、`3` 为行会；组队模式只能由队长创建，行会模式只能由会长创建。容量、模式、时限、空图回收时间或副本名称无效，以及两个模板重复声明同一副本名称时，整个 TXT 候选拒绝发布。

`CANMOVEECTYPE 副本名称` 检测当前人物是否有权进入已创建实例。`CREATEECTYPE 副本名称 有效分钟` 从 `FB` 模板创建隔离地图；同名个人副本按人物隔离，组队成员使用创建瞬间的成员快照，行会成员按当前行会身份访问。`MOVEECTYPE 副本名称 X Y` 通过真实传送链进入实例，超过模板规定的进入窗口后拒绝新进入；实例总时限到达会把仍在图中的人物送回创建前地图，已进入过的空实例按空图回收秒数提前释放。

`MOBECTYPEMON SELF|FBMAP|NPCMAP X Y 怪物 数量 范围 [名称颜色]` 只向当前人物有权访问的副本实例刷怪。`SELF` 指当前所在副本，`FBMAP` 指人物所属的最新副本，`NPCMAP` 指当前 NPC 所在副本；普通共享地图不能冒充副本。怪物、坐标、数量、范围或颜色无效时整条命令失败，不向其他人物的同名实例泄漏怪物。创建和移动结果继续调用翎风约定的 `@CreateEctype_*`、`@MoveEctype_*` 页面；仅当原脚本确实声明该页时才安排回调，避免覆盖人物正在进行的 NPC 会话。
