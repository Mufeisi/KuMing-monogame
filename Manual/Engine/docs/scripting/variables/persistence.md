# 私人持久变量与数据库

- 功能状态：实验性（VAR-03）
- 首次支持版本：开发版 2026-08-15
- 适用作用域：`U`、`T`

## 数据保存在哪里

U/T 不使用单独的 TXT 数据文件，而是跟随服务端当前选择的数据库 Provider：

| Provider | 实际存储 | 备份要求 |
|---|---|---|
| `Legacy` | 现有角色二进制账户档案中的版本化字段 | 沿用原账户数据库备份 |
| `SQLite` | `character_script_variables` 关系表 | 备份 SQLite 主库及现有 WAL 边界 |
| `MySQL` | `character_script_variables` 关系表 | 沿用 MySQL 一致性备份 |

关系表以 `character_id + variable_namespace + variable_key` 为主键。整数、小数和字符串分列保存；小数使用文化无关的十进制文本，避免数据库浮点类型造成几率尾差。

## 声明与实际值是两件事

- C# 启动脚本声明名称、类型和默认值，并支持现有脚本热重载。
- 数据库保存每个角色已经写入的实际值。
- 新增声明不要求重启服务器，也不会遍历并改写全部角色。
- 修改默认值只影响尚未写入该变量的角色；已有值保持不变。
- 修改已存在变量的类型会被原子热重载拒绝，旧声明继续工作。

私人变量可以在服务器启动阶段统一声明，因为声明不需要也不访问某个在线人物。登录 QM 只负责按当前人物读取或修改值。

## 使用方法

固定编号无需声明：

```text
MOV U0 100
INC U0 1
MOV T0 永久称号
```

命名小数先在 C# 脚本模块注册：

```csharp
registry.RegisterVariable(
    ScriptVariableScope.U,
    "DropRate",
    ScriptVariableKind.Decimal,
    "1.0");
```

随后所有 TXT NPC 使用统一命令：

```text
INC U.DropRate 0.25
CHECK U.DropRate >= 1.25
SENDMSG 6 当前私人掉落几率：<$FORMAT(U.DropRate,2)>%
```

## 保存与恢复时机

每次成功修改或清空 U/T 后，引擎请求现有账户自动保存。关闭 NPC、换图、小退和掉线不会清除值；正常账户保存、服务端重启加载以及角色归档/恢复都会携带值。

!!! warning "异常断电边界"
    自动保存请求不等同于每条命令都同步刷盘。突然断电时的最大数据窗口仍由现有账户自动保存周期和数据库持久性配置决定。关键运营操作应配合现有强制保存与备份流程。

## 限额与类型

- `U0-U499` 固定为 `Int64`。
- `T0-T499` 固定为字符串。
- 命名 `U.名称` 可声明 `Integer` 或最大 8 位小数的 `Decimal`。
- 命名 `T.名称` 应声明为 `String`。
- 每个角色最多保存 4096 个 U/T 实际值；超过配额时本次写入失败且旧值不变。

数据库中的异常单行会被跳过，不会阻塞整个角色列表加载。运维人员不应直接修改变量表；类型迁移应由正式迁移流程完成。
