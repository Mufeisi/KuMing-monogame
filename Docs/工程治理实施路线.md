# LyoCrystal 工程治理实施路线

- 状态：进行中
- 负责人：项目所有者
- 最后复核日期：2026-08-12
- 当前阶段：ENG-03
- 前置规范：[`工程开发规范.md`](工程开发规范.md)
- 事实源：本文只维护工程治理任务状态；产品功能状态由对应活动 PRD 维护

## 1. 目标

- 建立磁盘、解决方案、过滤器和 CI 一致的可信工程地图。
- 统一构建、测试、调试和文档入口，降低新人及 Agent 的理解成本。
- 把可机械检查的 `MUST` 规则逐步落到 CI 和代码托管门禁。
- 为客户端、服务端、启动器、微端、共享、测试和工具明确职责与所有权。
- 随产品任务渐进提取深模块，不阻塞正常功能开发。

## 2. 非目标

- 不一次性移动全部物理目录或替换命名空间。
- 不一次性拆分 `GameScene`、`PlayerObject` 等巨型类。
- 不重写协议序列化、渲染、脚本热更、微端、FairyGUI 或数据库迁移设施。
- 不制造独立治理平台、分析器或第二套任务系统。
- 不用工程整理覆盖既有产品缺陷、功能需求或历史证据。

## 5. ENG-02 工程分类

主解决方案使用逻辑目录表达架构，不改变物理路径：

| 分类 | 工程 |
|---|---|
| Clients | `Client_VorticeDX11`、`Client_MonoGame.Shared`、Android、iOS |
| Server | `Server.Library`、`Server.MirForms` |
| Shared | `Shared` |
| Launcher | `Launcher.PlayerShell.Core`、`Launcher.PlayerShell`、`Launcher.ThemeRuntime`、`Launcher.Editor` |
| MicroGateway | `MicroGateway.Core`、`MicroGateway.App` |
| Editors | `AutoPatcherAdmin`、`Controls`、`LibraryEditor`、`LibraryViewer` |
| Tests | `Base05.Tests`、`ShareProtocolCompat` |
| Tools | 四个正式工具工程 |
| WindowsIntegration | 七个 Windows 集成/门禁工程 |

`LyoCrystal.Windows.slnf` 继续表示现有 Windows 发布基线，不因主解决方案补齐而扩大 CI 构建面。新增过滤器只用于按子系统开发和验证。

## 6. 执行规则

1. 当前只执行状态为“进行中”的任务；不得提前进行物理目录移动。
2. 每项任务使用独立分支和提交，变更后按《工程开发规范》验证。
3. 状态变更必须有代码、配置、测试输出或可复核对比数据支持。
4. 发现产品缺陷只进入对应产品 backlog，不混入工程治理提交。
5. 每项治理任务完成后更新本文状态，并明确下一项。
