### 1.4 需要明确纠正的旧认知

- **不是"145 个未处理服务端包"**，而是差集 **275 − 246 = 29**；当前为一次性脚本统计，无自动审计工具（自动化留待 CI 上线，见 PROTO-02）。
- **不是"整库全删重插"**，而是"整域快照 Upsert + 按时间戳清理旧行"，且在主线程同步执行。
- **PC 端密码**：PC 端 `Settings.cs` **确实无条件读写 INI 明文密码**（v1.2 误判为"PC 不写密码"，v1.3 修正）；移动端受 `RememberPassword` 控制。结论：**两端正式版都禁止持久化密码。**
- **LevelEffects**：枚举声明分叉是事实，但**已检查的序列化两端均显式 UInt16**，未证实 wire-breaking；需审计全部使用点。
- **稳定 SDK 基线**：`global.json` 锁定 SDK 10.0.200/workload 10.0.201，活动工程不引用 preview SDK/包；BASE-06/07 的 TFM、MAUI/AOT 与 Windows 构建迁移已完成。
- **Android 最低 API**：`SupportedOSPlatformVersion=24.0`，真机 arm64 四态仍留给 RELEASE-03 最终设备验收。

## 2. 目标架构

### 2.1 架构愿景（12 个月后的样子）

```
┌─────────────────────────────────────────────────────────────┐
│                     目标架构（渐进收敛）                       │
│                                                             │
│  PC 客户端           移动端(Android/iOS)        Server        │
│  ─────────           ─────────────────         ─────────     │
│  Client_VorticeDX11  Client_MonoGame.Shared   Server.Library │
│  │                  │                        │              │
│  └─► 唯一协议源 ◄────┘                        │              │
│      Shared.Protocol（包/ID/DTO/跨端协议枚举） │              │
│      C# 为事实源，wire manifest 自动生成+审计  │              │
│                                              ▼              │
│                                    脚本层（Roslyn 热更）      │
│                                    ┌─────────────────────┐   │
│                                    │ 脚本：NPC/任务/掉落/   │   │
│                                    │ 配方/经济/赛季规则层   │   │
│                                    └─────────────────────┘   │
│                                    C# 核心：怪物AI/技能/攻城   │
│                                    保持硬编码+暴露 Hook        │
│                                    Core Activity Service：    │
│                                    状态机/计分/幂等/持久化     │
│                                              │              │
│                                    持久化（SQLite 生产化）     │
│                                    WAL/单写者/备份/恢复/RPO·RTO │
│                                    运行时：.NET 10 LTS       │
└─────────────────────────────────────────────────────────────┘
```

- **唯一协议源**：新增纯净 `Shared.Protocol`（包/ID/DTO/真跨端协议枚举）。**事实源 = C# 代码**；wire manifest 由工具从 C# 自动生成，仅用于漂移审计与兼容测试。**不做"manifest 为源生成 C#"**（避免双维护分叉）。
- **脚本边界**：脚本 = 旁路 Hook + 数据定义 + 活动**规则层**；C# 核心 = 引擎逻辑 + Hook 暴露点；活动**状态机/计分/结算/幂等**在 Core Activity Service，SQLite 持久化，客户端只展示不判定。
- **持久化**：SQLite 生产化（WAL/专用单写者/RPO≤5min/RTO≤30min/备份恢复演练）为主力，MySQL 作为明确触发门槛后的切换目标。
- **可观测性**：日志从空壳恢复为结构化落盘（轮转/保留/过滤 PII）；保存/脚本/网络/队列全部有指标；GM Web 只读仪表盘（独立管理员凭据，默认只监听回环/内网）。
- **可复现构建**：源码基线 + 外部资源包来源/版本/哈希/获取方式 + 平台 CI 矩阵（Windows/Android/macOS/通用测试）+ **.NET 10 LTS 发布基线（迁移是 P0 阻塞任务）**。

### 2.2 协议层收口设计（ADR-1 落地方案）

```
Shared/                         ← 唯一协议源（已存在，继续作为源）
  Shared.Protocol               ← 新增纯净协议子集：Packet/ID/DTO/跨端协议枚举
  平台差异（Language/资源路径/渲染枚举）← 留在各端平台层，从协议子集中分离
```

- **事实源 = C#**；wire manifest 由生成器从 `Shared.Protocol` 自动产出，用于跨端漂移审计与序列化兼容测试。**禁止手工双维护。**
- 先盘点后收口：先产出机器可读 wire manifest（包 ID、字段顺序、字段类型、枚举底层类型、枚举数值、nullable/数组编码、V1/V2 可用范围），建立序列化兼容测试，再逐步切换消费者。**禁止一次性大爆炸替换。**
- 已知分叉 `LevelEffects`：以 wire manifest 为准先审计全部使用点，确认是否 wire-breaking，再由兼容测试兜底，最后统一源码。
- 不要求 `diff Shared/ Share/` 为空（移动端本就有平台差异）。
- 不做 144K 行命名空间替换：先引用对齐 + 双命名空间兼容期。

## 3. 技术边界（红线）

> 与 PRD 不同，这里只讲"永远不许违反"的架构纪律。

1. **协议边界**：`Shared.Protocol`（或收敛后的 `Shared/`）是唯一事实源，由自动生成的 wire manifest 审计。新包/新枚举/新字段必须先改协议源 + 重新生成 manifest + 跑兼容测试，再同步移动端。**禁止在 `Share/` 副本或各端直接改协议。**
2. **主循环边界**：服务器单线程游戏状态 + 怪物分线程。玩家/Hero/NPC/宠物只在主线程处理；跨线程访问必须 `InvokeOnMainThread`。**禁止在怪物线程直接读写玩家状态。**
3. **脚本边界**：脚本只做旁路 Hook + 数据定义 + 活动规则层。核心玩法（怪物 AI/技能/拍卖/攻城）保持 C# 硬编码 + 暴露 Hook；活动状态机/计分/幂等/持久化在 Core Activity Service。**禁止脚本重写核心引擎逻辑、禁止脚本直接写持久化状态。**
4. **迁移边界**：txt→C# 双轨并存、`NpcScriptCoverage` 逐批切换；DB 改表必须新增 `SchemaMigration`。**禁止大爆炸切换、禁止手改库。**
5. **渲染边界**：PC 所有绘制走 `DXManager` 接缝；移动端走 `SpriteBatchStack`。**禁止业务代码绕过接缝直连 D3D/GPU。** 移动端贴图创建帧预算（`MobileMaxTextureCreatesPerFrame`）不得破坏。
6. **安全边界**：生产密钥只来自受保护密钥存储（CI 短暂获取），禁止常驻普通环境变量；正式服禁止默认 GM 密码与公网 HTTP 管理端点；管理 API 默认只监听回环/内网；新密码一律 Argon2id；凭据不通过未加密网络传输（**公网默认关闭 V1 明文登录，或 V1 仅内网/白名单/安全隧道，见 PRD SEC-02**）。
7. **工程卫生**：`.sln`/`.slnf` 与磁盘必须同步；版本集中管理；不再产生幽灵工程。**新工程入库必须同步解决方案。**
8. **数据边界**：发布版数据写库必须满足 RPO/RTO 约定（见 PRD P3 数据库阶段），单写者进程锁，禁止多进程写同一 SQLite。
9. **运行时边界**：**发布物禁止依赖 Preview SDK/Runtime/NuGet**；net10 迁移已完成，Android 正式发布仍需满足 RELEASE-03 设备验收。
