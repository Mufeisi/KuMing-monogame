## 1. 目标与用户价值

版本作者在发布前运行一次只读检查，即可发现跨领域悬空引用、非法数值和资源摘要漂移。每条问题必须具有稳定诊断码、严重级别和可定位的文件或实体位置，避免等到服务启动或玩家进入内容后才暴露错误。

## 2. 范围

### 2.1 做

1. 复用服务端现有地图、怪物、物品、NPC 与 `ScriptRegistry` 事实对象。
2. 校验地图记录和地图文件、移动目标、刷怪、NPC 脚本、NPC 商店、掉落、配方及启动资源引用。
3. 输出稳定代码、错误/警告/建议、中文信息和具体源位置，并保证结果顺序稳定。
4. 使用一套故意破坏的样例覆盖每类首批规则，使用正常样例证明无阻断误报。
5. 保持领域服务只读；文件检查只读取元数据、内容和摘要，不修改项目或运行数据。

### 2.2 不做

1. 不开发 UI、内容编辑器、自动修复器、通用规则引擎或第二套配置模型。
2. 不修改地图、数据库、脚本、掉落、商店、配方和资源文件。
3. 不开始 LEG-03 网关治理或 LEG-06 内容工作台。
4. 不把诊断信息自动升级为生产发布阻断；真实消费者接入必须保持调用方可选择门禁策略。

## 3. 实现与架构约束

1. 领域服务位于 `Server.Library`，输入直接使用现有领域类型和脚本注册表。
2. 启动资源使用调用方提供的路径、大小和 SHA-256 只读投影；该投影不是持久化事实源。
3. 不创建新的常驻进程、分析平台或配置文件；测试样例在测试生命周期内临时生成。
4. 诊断码一经进入测试即视为对消费者的兼容契约；新增规则新增代码，不复用旧代码改变语义。
5. 所有检查必须可重复、无副作用，并按代码和源位置稳定排序。

## 4. 首批规则

| 域 | 规则 |
|---|---|
| 地图 | 地图文件存在且可读取；移动目标地图存在 |
| 刷怪 | 怪物存在；数量、范围、刷新时间和坐标有效 |
| NPC | 所属地图存在；坐标有效；TXT 或 C# 主页面脚本存在 |
| 商店 | 商店所属 NPC 存在；商品和合成产出引用的物品存在 |
| 掉落 | 物品存在；概率、数量、权重、目标互斥和分组非空有效 |
| 配方 | 成品、材料和工具存在；产出与材料数量有效 |
| 启动资源 | 清单项路径安全；文件存在；大小与 SHA-256 一致 |

## 6. 退出条件

1. 故意破坏的样例对第 4 节每一类规则至少产生一条预期诊断。
2. 正常样例零错误，且不存在阻断误报。
3. 每条诊断可定位到具体文件、地图/刷新点/NPC、掉落项、商店项、配方项或资源项。
4. 重复执行结果顺序与诊断代码稳定。
5. `Server.Library` 与受影响测试通过，仓库中没有新增构建产物、秘密或外部资源。

## 7. 回滚

回滚本任务提交即可移除预检能力。领域服务不写入数据，不需要数据回滚；调用方尚未将预检设为生产强阻断，因此回滚不会改变现有发布数据或运行状态。
