## 1. 目标与完成定义

版本作者从现有桌面作者工作台选择一个声明式测试实例，完成预检、依赖顺序启动、健康确认、分组件日志定位、正常停止和失败回滚。档案只保存秘密引用，不保存秘密值；健康不能只依据进程存在或窗口位置。

完成时至少一个隔离测试实例通过真实隐藏进程验证，正式环境默认拒绝自动启动，共享账号库、生产部署与直接杀进程不在本阶段范围。

## 2. 设计边界

- `Launcher.InstanceManagement` 拥有实例档案、预检和运行状态机；作者工作台只导航和调用，不复制状态。
- 档案独立存放于项目 `instances/`，不扩大启动器项目 JSON，不写入秘密值。
- 端口使用“基础端口 + 实例偏移”；组件声明共享或独占依赖、启动顺序、健康探针、日志和版本。
- 启动失败按已启动组件的逆序停止；优雅停止优先，强制停止必须显式授权并留下审计事件。
- 正式环境运行属于独立生产授权；本阶段只读预检，自动运行失败关闭。

## 3. 实施门禁

### `GATE-INSTANCE-PROFILE`

- `INSTANCE-01`（已关闭）：实例档案、原子存储、路径/端口/秘密/依赖预检与稳定诊断。

退出条件：合法测试档案可保存重载；非法格式、路径越界、端口冲突、依赖环和秘密值在启动前被阻断。

### `GATE-INSTANCE-RUNTIME`

- `INSTANCE-02`：依赖拓扑、进程启动、TCP/HTTP 健康、超时、分组件日志、逆序停止和失败回滚。

退出条件：临时目录中的真实隐藏组件按序进入健康，失败组件触发已启动组件回滚；运行时长、版本、日志与状态可观察。

### `GATE-INSTANCE-OPERATIONS`

- `INSTANCE-03`：接入作者工作台，交付实例选择、预检、启动、刷新健康、查看日志、正常停止入口和测试环境外环。

退出条件：作者工作台可管理一个隔离测试实例；正式秘密不进入档案或日志；不使用可见桌面自动化完成验收。

## 4. 验证与回滚

快内环运行档案/状态机测试、受影响项目 Release 构建、`git diff --check` 和 Markdown 链接检查。`GATE-INSTANCE-RUNTIME` 使用真实隐藏子进程；阶段末只运行一次完整测试环境外环。每个 `INSTANCE-*` 独立提交，可按逆序回滚；档案为新增旁路，回滚代码不修改服务端数据库或运行数据。
