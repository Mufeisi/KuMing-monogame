- 上位路线：[`传奇类参考源码吸收开发路线.md`](传奇类参考源码吸收开发路线.md)

## 1. 目标与用户价值

版本作者在既有编辑器内完成地图、NPC、刷怪、掉落和资源的“编辑→校验→差异→保存→重载→冒烟”闭环。保存前即可发现悬空引用和非法值，所有变更可审查、可取消、可恢复，不再依赖关闭窗体时隐式写回。

## 2. 范围

### 2.1 做

1. 地图与刷怪：增强 `VisualMapInfo`，提供编辑会话、撤销/重做、保存前校验、差异预览、显式保存与取消，并渐进补齐出口、NPC、刷怪和矿区叠层。
2. NPC 与脚本：提供对话预览、链接检查及脚本/资源跳转，复用现有脚本调试器。
3. 掉落：在现有 DropBuilder 和脚本定义上提供概率展开、期望产出、模拟及修改前后对比。
4. 资源：在 LibraryEditor 和现有资源清单上提供缺失引用、反向引用、重复与未使用候选；默认不自动删除。
5. 跨域导航：LEG-02 诊断可跳转到拥有记录的既有编辑器。

### 2.2 不做

1. 不建立第二套地图、NPC、刷怪、掉落、任务或资源事实源。
2. 不重写地图格式、脚本运行时、掉落运行时、LibraryEditor、协议、数据库或渲染接缝。
3. 任务作者闭环、旧内容导入和套装编辑必须另行激活，不与本阶段主闭环捆绑。
4. 不开始 LEG-07 自定义游戏 GUI 或 LEG-08 技能工具。

## 3. 实施顺序

1. `CONTENT-01` 地图与刷怪编辑会话：显式保存/取消、撤销/重做、校验、差异和重载。已实施，证据见 [`../Evidence/LEG-06-20260813/CONTENT-01.md`](../Evidence/LEG-06-20260813/CONTENT-01.md)。
2. `CONTENT-02` 地图叠层与跨域导航：出口、NPC、刷怪、矿区可切换显示，诊断可定位。
3. `CONTENT-03` NPC 与脚本闭环。
4. `CONTENT-04` 掉落分析闭环。
5. `CONTENT-05` 资源引用闭环。
6. `CONTENT-06` 真实内容版本测试服冒烟与阶段收口。

每项使用独立提交；上一项门禁未关闭时不得开始下一项。

## 4. 架构与数据约束

1. 编辑会话是唯一变更接缝：窗体提交当前控件投影，会话负责快照、校验、差异、提交和取消。
2. LEG-02 稳定诊断码继续作为保存前校验依据；新增规则不得改变旧诊断语义。
3. 保存只通过现有服务端持久化入口执行；不修改 Schema，不绕过主线程写约束。
4. 关闭、取消或校验失败不得改变原始事实对象；保存失败必须保留原始对象和可重试草稿。
5. 参考源码只用于行为与工作流参考；不复制 Delphi 代码、资源、协议或私有格式。

## 5. 验证

快内环：编辑会话领域测试、受影响 Windows 表单集成测试、`Server.Library` 与 `Server.MirForms` 构建。

阶段外环：以一张真实地图和一个真实 NPC/怪物版本完成修改、校验、差异、保存、重载和测试服冒烟；保存前备份源文件并记录恢复验证。

## 6. 退出条件

1. 地图、NPC、刷怪、掉落和资源五类工作流均能从编辑进入校验、差异、显式保存及重载。
2. 非法内容被保存前校验阻断，诊断可定位到文件、地图或实体。
3. 取消、关闭和保存失败不改变原始内容；成功保存后重载结果与确认差异一致。
4. 一张真实地图及一个真实 NPC/怪物版本在测试服冒烟通过，且所有源文件均可恢复。
5. 受影响构建、测试、窗口工件和证据链接全部通过。

## 7. 回滚

每个 `CONTENT-*` 切片均为独立提交，可逐项回滚。涉及真实内容保存时先生成受控备份；代码回滚不等同数据回滚，必须用对应源文件备份恢复并重新加载验证。
