## 1. 任务简报

- 目标：让版本作者在同一项目页面理解、配置、预检并验证客户端发行体和各区服微端入口。
- 用户价值：发布前即可看清客户端核心、资源包、资源版本、签名身份、默认入口与区服覆盖的关系，并从错误直接进入可修复位置。
- 做：发行体概览、默认及备用入口、区服覆盖、资源目录扫描、版本与签名一致性检查、入口连通性预检、测试资源发布，以及 PC/Android 同版本获取、缓存命中与失败回退冒烟。
- 不做：重写或内嵌 `MicroGateway`；在生成启动器时编译、复制、打包或部署微端服务程序；改变既有签名格式；把游戏登录地址与微端入口合并。
- 方法约束：复用既有 `Launcher.ThemeRuntime`、`ProjectReleasePublisher`、签名、防降级、原子切换和回滚接缝；资源扫描不得阻塞作者工具界面。
- 风险等级：中高，涉及发布预检、跨端资源版本和网络失败诊断。
- 完成定义：满足 `GATE-MICRO-UX` 四项退出条件，并保存发行体概览、预检错误、PC/Android 获取日志和缓存命中对比工件。
- 语言：任务交流、文档、状态和提交信息均使用中文。

## 2. 实施顺序

1. `MICRO-UX-01/04`：交付模式首屏提供发行体概览；后台扫描资源目录，展示核心缺失、重复项、核心体积和完整体积。
2. `MICRO-UX-02/06`：在概览中展示默认/备用入口和区服覆盖，预检问题可直接定位到资源、入口、区服或签名设置。
3. `MICRO-UX-03`：增加主/备用入口连通性以及远端资源版本、签名身份一致性预检；失败必须区分入口、区服和资源包。已实施，证据见 [`../Evidence/LEG-05-20260813/MICRO-UX-03.md`](../Evidence/LEG-05-20260813/MICRO-UX-03.md)。
4. `MICRO-UX-05`：生成测试资源发布，完成 PC 与 Android 对同一签名资源版本的首次获取、缓存命中和失败回退冒烟。
5. 阶段回归：既有签名、防降级、原子切换、离线发布和回滚测试保持通过。

当前首个垂直切片以第 1、2 项的本地可验证部分为范围；网络预检和跨端冒烟沿用后续顺序，不提前伪造通过状态。

## 3. 边界与回滚

发行体概览只读取资源目录，不写入或复制客户端文件。玩家入口生成继续只生成玩家壳及既有完整客户端包；独立微端部署仍由现有高级工具显式触发。每个垂直切片使用独立提交，失败时可逐提交回滚，不改变项目 JSON、协议或数据库格式。
