## 1. 目标与用户价值

版本作者在现有技能工具中理解技能的条件、目标、范围、结果、时间和表现，并只修改经过白名单批准、可由服务端校验且具有战斗回归的安全字段。至少一个现有技能最终完成读取、预览、安全修改、保存、重载和 PC、Android、服务端一致性验证；客户端始终不拥有战斗计算权威。

## 2. 任务简报

- 目标：依次关闭 `GATE-SKILL-READONLY`、`GATE-SKILL-VISUAL` 和 `GATE-SKILL-SAFE`，交付一个现有技能的安全作者闭环。
- 用户价值：作者先理解真实运行行为，再进行受控修改；非法参数在保存前被阻断，客户端不能借配置修改取得战斗权威。
- 做：只读投影、范围网格、表现时间线、白名单编辑会话、服务端校验、协议兼容、战斗回归及一个真实技能的三端验收。
- 不做：新建技能、技能强化规则、核心技能数据驱动重写、第二套战斗解释器、第二套协议或客户端权威结果。
- 方法约束：复用 `MagicInfo`、现有服务端技能执行、现有 PC/Android 表现和 `Server.Authoring`；每个切片独立提交，上一门禁未关闭不得进入下一门禁。
- 风险等级：高；后续切片涉及战斗参数、服务端权威和跨端表现。本阶段首切片为只读中风险变更。
- 预估成本：7～12 人周；这是拆分依据，不是发布日期承诺。
- 完成定义：一个现有技能完成全闭环，所有可写字段具有服务端校验、兼容证明和战斗回归，客户端只显示服务端批准的结果。
- 验证方式：纯规则测试、窗体集成、服务端战斗回归、协议兼容、PC/Android 表现对比及测试服真实技能冒烟。
- 回滚方式：各切片独立回滚；编辑保存使用原始快照、差异确认和可恢复备份；协议进入兼容窗口后按专项兼容说明处理。
- 语言：全部交流、规格、状态、证据与提交信息使用中文。

## 3. 当前基线与不变量

1. 技能配置事实源是 `src/Server/Server/MirDatabase/MagicInfo.cs`；不得建立第二份可写技能模型。
2. 服务端技能行为继续由现有 `Server.MirObjects` 实现拥有；本阶段只建立作者投影、诊断和受控编辑接缝，不复制技能执行器。
3. 现有 `MagicInfoForm` 会在文本变化时直接修改事实对象并在关闭时保存；安全编辑必须以快照会话渐进替换，取消、关闭和校验失败不得改变原对象。
4. 协议只修改 `src/Shared/Shared/` 事实源；玩家状态和战斗结果只由服务端主线程决定。
5. PC 与 Android 只消费同一份经过服务端批准的技能投影，不各自解释一套战斗语义。
6. “作者新建技能”“技能强化规则”和核心技能数据驱动必须另立高风险 ADR 与 PRD，不得由本阶段顺带实现。

## 4. 实施顺序

### 4.1 `GATE-SKILL-READONLY`：真实技能只读理解

1. `SKILL-01`：在现有 `MagicInfoForm` 增加只读理解页，展示 `MagicInfo` 原始字段、0～3 级消耗/冷却/结果区间、技能书引用和服务端权威入口。已完成，证据见 [`../Evidence/LEG-08-20260814/SKILL-01.md`](../Evidence/LEG-08-20260814/SKILL-01.md)。
2. `SKILL-02`：展示目标条件、中心类型、附加点和作用范围网格；未知行为明确标为未建模，不猜测。已完成，证据见 [`../Evidence/LEG-08-20260814/SKILL-02.md`](../Evidence/LEG-08-20260814/SKILL-02.md)。

`GATE-SKILL-READONLY` 已关闭。选择任一现有技能都能看到配置、等级结果、资源引用和空间档案；已核对技能显示目标条件、中心和网格，未核对技能明确失败为“未建模”且不根据 `MagicInfo.Range` 猜测。只读投影不修改事实对象。

### 4.2 `GATE-SKILL-VISUAL`：跨端表现预览

1. `SKILL-03`：展示施法、飞行、命中、持续效果和音效时间线，并标明 PC/Android 资源引用与缺失项。
2. `SKILL-04`：以一个真实技能完成范围和时间线的 PC/Android 对比，差异可定位到配置、代码或资源拥有者。

退出条件：同一技能的空间与时间表现可在作者工具预览，并与 PC、Android 实际表现核对；预览不参与战斗裁决。

### 4.3 `GATE-SKILL-SAFE`：白名单编辑闭环

1. `SKILL-05`：建立技能编辑会话、白名单字段、校验、差异、显式保存、取消、重载和失败恢复。
2. `SKILL-06`：每个可写字段补齐服务端重验、协议兼容和战斗回归，以一个真实技能完成 PC、Android、服务端一致性与测试服冒烟。

退出条件：至少一个现有技能完成读取、预览、安全字段修改、保存、重载和三端一致性验证；取消或失败不改变原始配置；客户端无法决定伤害、目标、范围、冷却或状态结果。

## 5. 验证与回滚

快内环依次运行只读投影/编辑会话领域测试、受影响窗体测试、`Server.Library` 与 `Server.MirForms` Release 构建、协议 manifest 校验（仅触达协议时）和 `git diff --check`。阶段慢外环只在对应门禁关闭时运行真实 PC、Android 与隐藏测试服验证。

每个 `SKILL-*` 切片使用独立提交。只读切片可直接回滚代码；写入切片必须在保存前保留原始快照和受控备份，代码回滚与配置恢复分别验证。
