## 1. 目标与用户价值

修复并关闭“玩家入口完成选区后不能可靠进入游戏”的真实阻断，建立可重复的最小链路探针。版本作者应能生成玩家入口，玩家应能通过该入口完成启动、登录、选角、进图、移动一次和正常退出；失败时应能定位到启动器、进程、登录、选角、进图或资源阶段。

## 2. 范围

### 2.1 做

1. 复用现有玩家入口、PC 客户端、服务端、微端和 `src/Shared/Shared/` 协议事实源。
2. 先建立能重现当前阻断的自动化或集成证据，再做最小修复。
3. 自动探针覆盖启动参数、工作目录、所选区服、登录、角色列表、开始游戏、进图、一次移动、心跳、退出和进程状态。
4. 真实客户端覆盖完整客户端、首次安装核心、缓存命中和微端回退；每个场景记录阶段耗时与失败原因。
5. 以现有启动器生成一个真实玩家入口，放入完整 PC 客户端根目录完成一次人工可观察冒烟。
6. 证据脱敏；账号密码、微端访问材料、数据库内容和机器秘密不得写入仓库。

### 2.2 不做

1. 不复制 91、BLUE 或其他参考源码的协议、封包、加密、线程或资源实现。
2. 不修改 `Share/` 历史协议副本，不为测试改写协议。
3. 不开始项目预检、网关治理、启动器画布增强、游戏 GUI、技能或内容工作台。
4. 不清理或覆盖外部测试根已有账号、角色、数据库、地图、日志、备份或资源。
5. 不把普通 `bin/` 输出、UI 截图或登录页可达冒充进图验收。

## 4. 清洁室与架构边界

参考源码只用于中文描述状态、失败场景和不变量。本任务独立使用 LyoCrystal 的现有类型和接缝实现，不复制 Delphi 代码、资源、私有协议常量或皮肤。协议事实源保持在 `src/Shared/Shared/`；玩家权威状态只由服务端主线程修改；渲染继续经过 `DXManager`；微端、脚本和发布链均复用现有实现。

## 5. 可观察状态机与失败判据

| 阶段 | 成功信号 | 失败分类 |
|---|---|---|
| 玩家入口 | 真实生成入口启动且选区可操作 | `launcher`：入口校验、选区或自托管失败 |
| 游戏进程 | `Client.exe` 从内置核心启动，工作目录为校验后的完整资源根 | `process`：未启动、提前退出、参数或工作目录错误 |
| 登录 | 服务端接受专用测试账号并返回角色阶段 | `login`：连接、TLS、凭据、限流或响应超时 |
| 选角 | 角色列表可见并接受开始游戏 | `character`：列表、建角或开始游戏失败 |
| 进图 | 收到游戏状态与地图，玩家对象可移动 | `enter-game`：状态切换、地图或实体初始化失败 |
| 资源 | 所需本地资源可读；微端场景可下载或回退 | `resource`：缺失、摘要、缓存、下载或回退失败 |
| 退出 | 客户端正常退出，会话标记清理，再次启动不受阻 | `shutdown`：进程残留、会话或替换标记未清理 |

任一阶段超时、未出现成功信号、进程非预期退出或资源校验失败均判为失败。自动探针必须返回非零退出码并输出上述稳定分类；原始协议载荷、密码和令牌不得进入输出。

## 6. 实施顺序

1. 在现有 `Launcher.PlayerShellIntegration` 和 `Launcher.PlayerShellGateL0` 中定位已覆盖的启动、资源根与会话行为，补充当前阻断的失败测试。
2. 只修改阻断链路所需的现有模块；若候选修复已存在于历史分支，按差异审查后等价移植，不新建平行启动系统。
3. 增加最小协议探针；优先放入现有测试或 `eng/WindowsIntegration` 接缝，不创建常驻通用测试平台。
4. 依次运行完整客户端、首次安装核心、缓存命中、微端回退四个自动场景。
5. 启动受控测试服，生成真实玩家入口，完成登录、选角、进图、移动一次、退出和再次启动冒烟。
6. 将脱敏输出、截图和摘要归档到 `Docs/Evidence/LEG-01-<日期>/`，完成规格审查后再申请合并。

## 7. 验证与证据

快内环：

```powershell
dotnet test eng/WindowsIntegration/Launcher.PlayerShellIntegration/Launcher.PlayerShellIntegration.Windows.csproj --configuration Release
dotnet test eng/WindowsIntegration/Launcher.PlayerShellGateL0/Launcher.PlayerShellGateL0.Windows.csproj --configuration Release
```

受影响模块构建和阶段末外环：

```powershell
dotnet build LyoCrystal.Launcher.slnf --configuration Release
pwsh -NoProfile -File Tools/ResourceBaseline.ps1 -Action Validate -Scope All
```

`Validate All` 会读取大型外部资源，预计超过快内环成本，只在阶段末、资源发生变化或明确重试时执行。真实冒烟证据至少包含：源码提交、三个运行制品摘要、服务端实际监听、玩家入口启动、进图后地图/角色可见、一次移动、正常退出、再次启动和失败分类输出。截图必须避开账号、密码、聊天及其他个人数据。

## 8. 退出条件

以下条件必须同时满足：

1. 自动探针覆盖并通过启动器、进程、登录、选角、进图、资源和退出状态。
2. 完整客户端、首次安装核心、缓存命中和微端回退四个场景有可复现结果。
3. 一次真实生成的玩家入口完成“选区→启动→登录→选角→进图→移动一次→退出→再次启动”。
4. `GATE-LAUNCH` 五项退出条件全部有代码、测试、截图或运行输出证据。
5. 失败时能稳定返回 `launcher`、`process`、`login`、`character`、`enter-game`、`resource` 或 `shutdown` 分类。
6. 未提交秘密、账号密码、运行数据库、外部授权资源或普通构建产物。

## 9. 回滚

代码回滚到任务开始提交即可关闭新探针或修复。真实测试只新增专用账号/角色并保留现有数据，不通过删除数据库回滚。资源若必须更新，先建立带时间戳备份并以现有资源摘要验证；失败时恢复原目录并复核摘要。启动器替换继续使用现有 last-known-good 与原子替换机制。任务不执行正式发布；合并和发布均需单独确认。
