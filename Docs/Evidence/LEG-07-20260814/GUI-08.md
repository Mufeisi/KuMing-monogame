# GUI-08 服务端窗口会话证据

- 执行日期：2026-08-14
- 切片：`GUI-08`
- 分支：`codex/leg-07-gui-session`
- 语言：中文

## 交付工件

1. `CustomGuiSessionController` 以单个 `MirConnection` 为玩家边界，服务端生成窗口实例和 128 位随机数，并绑定 GUI 文档/修订、签名包序列、状态修订、绝对期限及请求序号。
2. `MirConnection.ProcessPacket` 在现有游戏主线程接收 `CustomGuiAction`；登出、软断线和硬断线清理会话，连接主循环处理自然过期和运维停用。
3. 单玩家最多八个活动窗口、最长三十分钟；同文档替换、客户端关闭、包版本切换、自然过期和 Kill Switch 均发送明确关闭原因。
4. 开窗初始状态及返回描述使用独立深拷贝；调用方不能在包入队后篡改待发送事实。合法但未登记业务处理器的动作明确拒绝，不在 `GUI-09` 前伪报业务成功。

## TDD 与失败关闭

测试先引用尚不存在的 `CustomGuiSessionController`，得到编译失败；实现后逐步转绿。定向测试覆盖：服务端身份生成、同文档替换、严格连续序号、重放、乱序、随机数篡改、旧包版本、过期动作、定时过期清理、版本切换、客户端关闭、非游戏玩家、窗口数量/期限上限、处理器异常、状态所有权和既有 `Activities` Kill Switch。

稳定拒绝前缀为 `GUI08-SESSION-*` 与 `GUI08-ACTION-*`。业务处理器异常被转换为有界拒绝；请求序号已被消费，同序号再次提交按重放拒绝，避免失败路径成为重复执行入口。

## 主线程、Kill Switch 与回滚

所有动作由既有 `MirConnection.Process()` 游戏循环处理；会话层不启动后台线程，也不写玩家业务状态。运维门卫复用现有持久化 `Activities` Kill Switch：停用后不允许新开窗口，并以 `Invalidated` 关闭现有窗口。回滚时先停用该开关、确认活动会话清空，再逆序回滚本切片；客户端不会停留在等待业务结果的窗口中。

## 范围说明

本切片只判定玩家会话、窗口身份、GUI 版本、随机数、期限和重放。NPC、距离、活动时间、货币、次数、物品所有权及奖励事务由 `GUI-09` 实现；PC/Android 状态投影、脚本 Hook 和真实兑换场景分别属于 `GUI-10..12`。
