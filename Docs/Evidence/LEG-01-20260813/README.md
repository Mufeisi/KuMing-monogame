## 结论

真实 PC Release 客户端已在窗口模式下完成登录、选角、`StartGame`、地图与玩家信息接收、一次移动、正常退出，并以同一账号再次启动复验。两次进图均跨过外部服务端发出的当前客户端未知完整帧 `Id=275`，后续 `MapInformation` 与 `UserInformation` 未再被同一接收缓冲误丢弃。最终两次客户端退出码均为 `0`，对应时段没有新增异常；服务端记录角色连接与正常断开。

当前源码还通过现有配置器生成了真实单文件玩家入口，并关闭四类资源场景。真实运行暴露并修复了原版 Classic 入口忽略项目 `AutoStart` 的问题；修复后入口能从完整客户端资源根自动拉起游戏子进程。

## 根因与最小修复

1. `Packet.ReceivePacket` 遇到未知包时会返回 `null` 并清空剩余缓冲；外部服务端的 `Id=275` 与地图、玩家信息位于同一 TCP 缓冲，导致客户端连同后续已知帧一并丢弃。
2. PC 网络接收循环现在只跳过一个长度完整的未知帧，并继续解析同缓冲中的后续帧；协议编号与 `Shared` 事实源均未修改。
3. 进图首帧在 `UserInformation` 到达前不再读取空玩家对象；经验、负重及游戏帧绘制都有空状态保护。
4. 退出时先停止空闲更新/渲染循环，再释放 `DXManager` 与声音资源，消除关闭窗口后同帧继续创建地面纹理的竞态。
5. 冒烟覆盖只在 `LYOCRYSTAL_LEG01_SMOKE=1` 时启用；密码仅从进程环境读取，账号、角色、密码和冒烟开关不写回配置。
