# 启动器编辑器与独立微端开发设计

> 状态：设计已确认；2026-08-11 本机可实现能力及自动化已完成，必须依赖目标硬件/网络的项目按用户授权列为非阻断实机复验。准确边界见实施规格第 10 节。

## 1. 产品目标

以最少技术前置条件和最少操作步骤，让 GM 在 Windows 本地完成启动器品牌与主题编辑、远程区服维护、玩家入口生成、客户端发行以及独立微端部署。玩家只需获取一个 EXE；已有客户端自动复用，没有客户端时默认安装启动核心并通过微端按需补齐资源。

编辑器核心能力离线可用，不要求登录账号、云后台或在线数据库。离线时可以创建和编辑项目、预览主题、管理区服、扫描本地客户端、生成玩家 EXE、构建并签署发布版本、导出网关配置和项目恢复包；上传、线上复验和外网连通性检测需要网络。

编辑器可生成不携带私钥的离线部署包；GM 将其复制到联网服务器后，由微端网关或服务器端导入功能直接复验并发布，目标机器不需要源码、编译环境或完整编辑器。

编辑器可生成独立微端网关部署包，预置项目标识、建议端口、访问用户、缓存策略和信任公钥但不携带启动器签名私钥；GM 复制到微端服务器后选择完整客户端目录并一键启动，访问 Code 在目标 Windows 受保护存储中导入。

玩家从下载目录、桌面或临时目录运行单一 EXE 且未发现客户端时，只确认一次游戏位置；入口随后复制到稳定的受管理目录，启动核心、按需资源、缓存与日志均归入该客户端位置。再次运行原下载文件时自动转到正式入口，原文件不自动删除。

## 2. 已确认的主题能力

- 主题采用固定逻辑画布并随 Windows DPI 整体等比缩放。
- 区服选择模式由 GM 在主题中固定，支持侧边栏展开式和下拉选择式。
- 区服目录支持一级可选分组与 GM 发布的静态运营状态。
- 固定功能控件可以调整外观、位置、尺寸和显隐，但第一版不允许任意脚本或任意新增未知控件。
- 默认主题集成在玩家入口中；远程主题失败时依次回退到上次有效主题和内置主题。
- 静态图片支持 PNG、BMP、JPG；第一版不支持 GIF 或视频背景。
- 按钮默认从一张基础图片自动派生正常、悬停、按下和禁用状态，同时允许逐状态图片覆盖。
- GM 项目保留原始图片；发布包可自动优化，BMP 默认无损转换为 PNG，透明素材保持 PNG，照片背景可保持 JPG，并允许单图关闭优化。
- 公告默认由编辑器维护并随已签名启动器版本发布，支持多篇、置顶、发布时间、图片与 HTTP/HTTPS 链接；高级用户可改用外部网页，加载失败时回退到内置公告。
- 主题按钮只能绑定预定义安全动作，例如开始游戏、选区侧栏、游戏设置、账号相关网页、官网、客服、公告、检查更新、修复客户端、选择客户端位置、最小化和关闭；远程主题不得执行任意程序、脚本或命令行。
- 玩家游戏设置采用固定能力、主题化外观：分辨率动态枚举，支持窗口化、全屏及后续无边框窗口，并提供 FPS 限制、窗口置顶、自动开始、音量、客户端位置、微端缓存、客户端修复和高级日志；远程主题只能调整外观、位置和显隐，不得改变设置语义。
- 首版至少内置紧凑下拉式和宽屏侧边栏式两套可直接发布的完整模板，支持复制、另存、导入和导出；模板交换不得包含私钥、访问 Code 或玩家数据。
- 当前代码中写死的启动器外观必须完整迁移为“经典兼容模板”，在没有新主题配置时保持现有视觉与行为，并作为主题运行时的视觉回归基准。
- GM 通过预构建玩家入口模板一键生成专属单一 EXE，不依赖源码、Visual Studio 或 .NET SDK；编辑器嵌入项目引导信息、内置主题和信任公钥并执行生成后验证，代码签名证书为可选增强。
- GM 可设置玩家 EXE 文件名、ICO/PNG 图标、产品名称、文件说明、公司、版权、文件版本、产品版本、窗口标题和任务栏名称；编辑器负责图标转换、格式校验及生成后完整性检查。
- 玩家可任意重命名单一 EXE；项目身份、远程地址、信任公钥和内置主题均不得依赖文件名或同目录外置配置。
- 玩家 EXE 嵌入生成时最后验证通过的最低可用区服与微端快照；运行时按远程有效版本、上次有效缓存、EXE 内嵌保底的顺序选择完整配置。
- 玩家入口更新分为普通与强制两级：普通更新后台下载并在退出游戏或下次启动时应用，强制更新仅用于安全、格式不兼容或最低版本门槛；游戏运行期间不得替换 EXE，失败保留旧版。
- 每次远程发布形成不可变版本，完整上传和复验后才原子切换当前版本；编辑器保留历史、差异和备注，并通过生成更高单调序列的一键回滚恢复旧内容。

## 3. 编辑器工作流

- 新建项目提供可跳过的分步向导，覆盖品牌、客户端目录、交付模式、游戏与微端入口、主题模板、发布源、密钥恢复和工件生成。
- 跳过向导时创建带安全默认值的项目并直接进入完整编辑界面；缺失必填项只在生成或发布时集中阻止并给出中文修复入口。
- 支持只读导入现有客户端目录、`Mir2Config.ini` 和远程区服清单，预览后映射游戏、补丁、微端、默认设置与经典兼容主题；未知字段明确提示，敏感明文不进入项目文件，原目录不得被修改。

## 4. 已确认的微端能力

- 独立微端网关是默认生产部署；游戏服务端内置微端仅保留为兼容和测试模式。
- 网关默认以 Windows 图形界面 EXE 运行，并可一键注册为 Windows 服务。
- 一个网关实例只管理一套完整客户端资源库；GM 指定客户端目录后自动扫描。
- 扫描采用启动全扫、运行期增量监视、稳定文件纳入、索引原子切换和低频完整核对。
- 缓存采用自动限额的内存与磁盘两级缓存，缓存不得修改或删除完整资源库。
- 项目统一配置默认微端入口，区服可选高级覆盖，并支持一个可选备用入口。
- 正式部署兼容 HTTP、IP 与端口；HTTPS 为可选增强，不作为 GM 开服门槛。
- 只有启动核心阻断进入游戏；其他资源按需或后台补齐，并提供非阻断下载状态。
- 微端模式不向玩家提供主动下载全部资源的入口；完整客户端交付只能由 GM 在项目发行模式中选择，玩家不能在两种交付模式间自行切换。
- 网关提供可撤销的一键 URLACL、Windows 防火墙和本机连通性配置。
- 微端网关默认通过与 `/api/` 隔离的公开只读 `/launcher/` 路径托管已签名主题、公告和区服清单，使普通 GM 不必另装网站服务；外部静态网站或 CDN 仍可替代该发布源。

## 5. 分阶段交付门禁

1. **独立微端网关**：提取并复用现有微端处理、资源读取和客户端协议，交付可在另一台 Windows 服务器运行且能服务当前客户端的网关程序。
2. **主题运行时**：交付经典兼容模板、紧凑下拉模板、宽屏侧边栏模板，以及内置、缓存、远程整套回退的可运行玩家入口。
3. **GM 编辑器核心**：交付多项目、现有项目导入、区服与分组、状态、主题、公告、实时预览和微端部署包。
4. **单一玩家入口**：交付无需编译环境的一键 EXE 生成、品牌元数据、自动安置、客户端发现、启动核心和自更新。
5. **发布体系**：交付全自动签名、离线部署包、不可变版本、回滚、主备入口和线上复验。
6. **微端运维完善**：交付 GUI 与 Windows 服务双宿主、自动扫描、两级缓存、一键网络配置、只读状态和诊断。

每个阶段必须有可运行程序、测试或验证输出和可复核发布工件；不得用框架、计划或空界面代替退出条件。下一阶段不得为了方便而提前重写现有微端、Bootstrap、补丁、协议或渲染设施。
