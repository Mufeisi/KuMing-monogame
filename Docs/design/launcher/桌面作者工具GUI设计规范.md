# LyoCrystal 桌面作者工具 GUI 设计规范

- 状态：已接受
- 负责人：项目所有者
- 最后复核日期：2026-08-13
- 事实职责：统一启动器编辑器、微端发行工具、内容工作台及后续桌面作者工具的信息架构、视觉语言、交互和验收标准
- 适用范围：`src/Launcher/Launcher.Editor` 及后续明确引用本规范的 Windows 桌面作者工具
- 不适用范围：玩家启动器皮肤、PC 游戏内 HUD、Android 游戏 UI、服务端管理网页
- 上位约束：[`AGENTS.md`](../../../AGENTS.md)、[`工程开发规范.md`](../../governance/工程开发规范.md)、活动 PRD 与已接受 ADR
- 当前落地任务：[`LEG-04-启动器作者体验.md`](../../requirements/LEG-04-启动器作者体验.md)
- 语言：中文，代码标识符、快捷键及不可翻译产品名除外

## 1. 目的与强制等级

本规范把“专业、清晰、美观”转换为可实现、可审查和可回归的规则。后续界面变更必须先判断是否符合本规范，不得以个人审美、单张截图或某个商业产品的外观直接覆盖产品工作流。

- **MUST**：不满足不得宣称界面完成或合并。
- **SHOULD**：原则上满足；偏离必须在任务规格中记录原因和替代保障。
- **MAY**：可按场景选择，不为了视觉一致制造无用户价值的工作。

## 2. 设计原则

1. **工作对象优先**：画布、列表或正文是主表面，导航、工具和属性不得无条件挤占它。
2. **渐进披露**：高频命令直接显示，低频和危险命令进入分组菜单、设置页或确认流程。
3. **上下文一致**：对象树、画布、属性和状态栏必须表达同一选择；不允许多个选择事实源。
4. **直接操作并可恢复**：能在画布完成的动作优先直接操作；所有破坏性编辑必须支持撤销或明确确认。
5. **稳定胜过新奇**：模式、命令位置、术语和快捷键保持稳定，不追逐不适合 WinForms 的品牌动画或装饰。
6. **默认简洁，能力不丢失**：折叠次要表面时必须保留菜单、快捷键或恢复入口。
7. **状态不靠猜**：保存、脏状态、生成、错误、选择、缩放和后台任务必须可见。
8. **无障碍是默认质量**：键盘、焦点、高对比度、DPI 和屏幕阅读信息不是发布后的补丁。

## 3. 信息架构

### 3.1 固定工作模式

作者工具主窗口固定使用五种顶层模式。新增功能必须归入现有模式；只有跨至少三个独立工作流且无法合理归类时，才能通过规格评审新增模式。

| 模式 | 用户目标 | 允许内容 | 禁止内容 |
|---|---|---|---|
| 概览 | 从项目现状进入下一步 | 新手流程、资源选择、最近结果、关键风险、快捷生成 | 深层属性表、完整诊断日志 |
| 设计 | 编辑视觉和交互表面 | 对象树、画布、上下文属性、素材和布局命令 | 发布密钥、服务地址批量表 |
| 内容 | 编辑玩家可见业务内容 | 区服、公告、安全动作、默认设置 | 签名历史、画布图层 |
| 交付 | 生成、签名、发布和回滚 | 微端、版本、签名、离线包、恢复包 | 日常画布属性 |
| 诊断 | 定位问题并验证发布条件 | DPI 预览、预检、日志、证据和修复建议 | 不受控生产写入 |

模式切换 MUST 改变整个工作区；模式内部 MAY 使用二级标签，但二级标签只划分同一工作流的页面。主窗口不得横向堆叠项目、对象、设置和发布等不同层级的平级标签。

### 3.2 应用外壳

```text
┌ 当前项目 ▼ ───── 保存状态 ───── 全局主动作 ───── 更多 ┐
├ 概览   设计   内容   交付   诊断                         ┤
├──────────┬─────────────────────────────┬──────────────┤
│上下文左栏│          主工作表面          │上下文右栏    │
│对象/导航 │          画布/列表           │属性/检查器    │
├──────────┴─────────────────────────────┴──────────────┤
│结果状态 │ 选择/坐标 │ 缩放 │ 预检 │ 后台任务              │
└───────────────────────────────────────────────────────┘
```

- 顶部全局栏 MUST 单行常驻，显示当前项目、保存状态和当前最重要的全局动作。
- 模式栏 MUST 保持五项顺序不变；激活态不得只依赖文字颜色。
- 主工作表面 MUST 弹性占据剩余区域。
- 左右栏 MUST 与当前模式相关，支持调整宽度；设计模式右栏 MUST 可折叠。
- 状态栏 MUST 分区呈现，不能用一条不断覆盖的长句承担全部状态。

## 4. 布局与响应规则

所有数值均为 96 DPI 下的逻辑像素；系统缩放后等比生效。

### 4.1 尺寸基线

| 对象 | 默认 | 最小 | 最大/约束 |
|---|---:|---:|---:|
| 主窗口 | 1280×800 | 1100×700 | 支持最大化与 Windows Snap Layout |
| 顶部全局栏高度 | 36 | 32 | 单行，不自动变成两排 |
| 模式栏高度 | 36 | 32 | 五项完整可见 |
| 上下文命令栏高度 | 32 | 30 | 超出进入溢出菜单 |
| 左侧对象栏宽度 | 190 | 160 | 320 |
| 右侧属性栏宽度 | 250 | 220 | 360；可折叠为 0 |
| 状态栏高度 | 24 | 22 | 单行分区 |
| 面板分隔条 | 1 可见/4～6 可命中 | 4 可命中 | 鼠标悬停显示调整光标 |
| 常规点击目标 | 32×32 | 28×28 | 触控优先场景 SHOULD 为 40×40 |

### 4.2 断点

- **≥1280**：三栏完整显示，画布优先获得剩余空间。
- **1100～1279**：压缩工具文字、将次要命令移入菜单；右侧属性栏 MAY 自动折叠，但 MUST 提供明显恢复入口。
- **<1100**：不作为主工作窗口支持范围；若系统允许继续缩小，MUST 保持功能可达并允许滚动，不能静默裁切命令。
- 任何断点都不得改变画布逻辑坐标、对象尺寸或发布快照。

### 4.3 间距与对齐

- 基础间距单位为 4；常用间距只使用 4、8、12、16、24、32。
- 同组控件间距 4～8；不同组 12～16；页面外边距 16。
- 表单标签左对齐；数值字段按内容对齐；按钮文字居中。
- 不使用空格字符模拟对齐，不用多层边框制造分组。

## 5. 设计令牌

令牌是语义，不是某个控件的私有颜色。实现时应集中定义，禁止在业务窗体散布大量无名 RGB 常量。

### 5.1 字体

| 令牌 | 字体 | 大小/行高 | 字重 | 用途 |
|---|---|---|---|---|
| `Font.Ui` | Segoe UI Variable；不可用时 Segoe UI | — | — | 全局 UI |
| `Type.Caption` | `Font.Ui` | 12/16 | Regular | 次要说明、状态 |
| `Type.Body` | `Font.Ui` | 14/20 | Regular | 正文、字段、菜单 |
| `Type.BodyStrong` | `Font.Ui` | 14/20 | Semibold | 面板标题、强调 |
| `Type.Subtitle` | `Font.Ui` | 18/24 | Semibold | 页面标题 |

MUST 不使用小于 12px 的功能文字；中文界面默认左对齐；强调使用 Semibold，不用全大写、斜体或连续感叹号。

### 5.2 亮色主题颜色

| 令牌 | 建议值 | 语义 |
|---|---|---|
| `Surface.App` | `#F3F3F3` | 应用底色 |
| `Surface.Panel` | `#FAFAFA` | 工具面板 |
| `Surface.CanvasViewport` | `#24262B` | 画布外部视口 |
| `Surface.Input` | `#FFFFFF` | 输入与属性值 |
| `Border.Subtle` | `#D6D6D6` | 普通分隔 |
| `Border.Strong` | `#A8A8A8` | 焦点外的强分隔 |
| `Text.Primary` | `#1A1A1A` | 主文字 |
| `Text.Secondary` | `#5A5A5A` | 次要文字 |
| `Text.Disabled` | `#8A8A8A` | 禁用文字 |
| `Accent.Primary` | `#0067C0` | 选择与主动作 |
| `Accent.Hover` | `#005A9E` | 主动作悬停 |
| `Accent.SelectionFill` | `#DCEEFF` | 列表选中背景 |
| `Status.Success` | `#0F7B0F` | 成功 |
| `Status.Warning` | `#9D5D00` | 警告 |
| `Status.Danger` | `#C42B1C` | 错误/危险 |
| `Focus.Ring` | `#005FB8` | 键盘焦点 |

正文与背景对比度 MUST ≥4.5:1；非文字图形、边界和焦点提示 SHOULD ≥3:1。成功、警告、错误和选择不得只靠颜色，必须同时使用文字、图标或形状。

暗色和高对比度主题 MAY 后续实现，但所有语义令牌 MUST 保留主题替换能力；不得把亮色值直接当业务状态。

### 5.3 几何与层次

- 常规控件圆角 4；对话框或卡片 MAY 为 6～8；工具面板之间不使用大圆角。
- 常规边框 1；选择框 1～2；键盘焦点环至少 2。
- 阴影只用于对话框、浮层和拖拽预览；固定面板用色阶和分隔线区分。
- 动画只用于状态过渡，建议 100～200ms；不得阻断输入或影响自动化。

## 6. 命令与导航

### 6.1 命令分层

1. 全局栏：新建、保存、生成、当前项目和全局更多。
2. 模式栏：只切换工作模式，不执行保存或发布。
3. 上下文命令栏：仅作用于当前页面/选择，例如撤销、对齐和缩放。
4. 右键菜单：对象相关且可发现的快捷操作。
5. 对话框：需要多字段输入、确认或高风险说明的动作。

单个命令面 MUST 不超过 7 个直接可见命令组；同义命令在不同入口必须使用相同名称、图标、快捷键和启用状态。

### 6.2 主动作和危险动作

- 一个页面最多一个高强调主动作。
- “生成成品”可作为全局主动作；“删除”“覆盖”“轮换密钥”等不得使用主强调色伪装成普通继续操作。
- 破坏性动作 MUST 说明对象、影响和恢复方式；可撤销的普通删除优先直接执行并提供撤销，不重复弹窗。

### 6.3 快捷键

| 快捷键 | 语义 |
|---|---|
| `Ctrl+S` | 保存项目 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销/重做 |
| `Delete` | 删除或隐藏当前选择，遵循可恢复语义 |
| 方向键 / `Shift+方向键` | 1/10 像素移动 |
| `Ctrl+0` | 适应窗口 |
| `Ctrl+1` | 100% 缩放 |
| `Ctrl+Shift+F12` | 最大化/恢复主工作表面 |
| `F6` / `Shift+F6` | 在左栏、主表面、右栏间循环焦点 |

所有可见命令 MUST 可由键盘到达；快捷键 MAY 扩展，但不得覆盖 Windows 通用编辑键。

## 7. 工具窗口与面板

每个工具面板由标题栏、可选命令区和内容区组成。

- 标题栏 MUST 表明内容，如“对象”“属性”；不能只靠位置让用户猜。
- 标题栏 SHOULD 提供折叠/恢复和面板菜单；搜索只在对象数达到需要时显示。
- 空面板 MUST 显示原因和下一步，例如“选择一个控件以编辑属性”，不能只留大片白色。
- 面板宽度调整 SHOULD 持久化到本机用户设置；项目文件不得保存个人工作区布局。
- 第一阶段只实现停靠、折叠和调整宽度；浮动、多屏停靠和任意拖拽布局为 MAY，不得成为 LEG-04 门禁。

## 8. 对象树

- MUST 使用树语义表达父子/层级；固定平级控件也应保留未来分组能力。
- 每行 SHOULD 包含类型图标、名称、显隐状态和锁定状态；显隐/锁定具有独立可点击目标和无障碍名称。
- 单击同步画布与属性选择；`Ctrl`/`Shift` 多选行为符合 Windows 列表惯例。
- 上下键移动焦点，左右键折叠/展开，空格切换选中；右键菜单提供对象动作。
- 当前选择在窗口失焦后仍须可辨认。
- 搜索过滤不得删除选择或修改文档；清除搜索恢复完整树。

## 9. 画布视口与直接操作

### 9.1 视口

- 画布 MUST 在视口中居中；视口与玩家启动器客户区使用同一坐标原点。
- MUST 提供适应窗口、100%、放大、缩小；缩放范围建议 25%～400%。
- SHOULD 支持中键或空格+拖拽平移、鼠标位置为中心缩放、网格/辅助线/吸附开关。
- 画布缩放只改变视图，不修改文档坐标或尺寸。
- 视口空白使用中性深色，不能与实际启动器背景混淆。

### 9.2 选择与操作

- 选框使用高对比细线和控制柄；对象名称默认显示在状态栏或悬停提示，不长期覆盖内容。
- 多选使用一个总体包围框并保留各对象轮廓；隐藏和锁定对象必须有不同视觉语义。
- 移动、缩放、对齐、分布和属性编辑 MUST 进入同一撤销历史。
- 拖拽时显示坐标、尺寸、吸附线；结束后状态栏显示最终值。
- 锁定对象不能通过画布、键盘、属性或批量命令绕过。
- 点击、框选、拖拽和控制柄命中区在四档 DPI 下 MUST 与视觉位置一致。

## 10. 属性检查器

- 属性按“标识、布局、外观、状态、资源”稳定分组；高频组在上。
- 字段显示中文名称，技术标识作为说明或高级信息，不直接暴露给普通 GM。
- 布尔值显示“是/否”或明确开关，不显示 `True/False`。
- 坐标和尺寸显示 `px` 单位；角度、百分比和容量使用对应单位。
- 颜色显示色块、值和选择入口；图片显示缩略图、替换、清除和定位文件入口。
- 多选共同值正常显示，不同值显示“多个值”；修改共同属性应用于全部可编辑选择。
- 继承或默认值 SHOULD 提供重置入口；无效输入就地解释，不在保存时集中抛出难定位错误。
- 只读字段具有只读语义，不伪装成禁用且不可复制的文字。

## 11. 状态、反馈与文案

### 11.1 状态模型

状态栏至少分为：结果消息、选择摘要、坐标/尺寸、缩放、保存状态、预检状态。长任务使用进度和取消入口，不冻结主窗口。

- 成功：说明完成对象和输出位置。
- 警告：说明风险，但不把可继续状态写成失败。
- 错误：先说发生了什么，再说如何恢复；保留可复制的技术详情入口。
- 保存状态固定使用“已保存”“有未保存修改”“正在保存”“保存失败”。
- 同一位置不得频繁闪烁或用消息覆盖仍需处理的错误。

### 11.2 中文文案

- 使用动作+对象：“保存项目”“生成玩家入口”，避免“确定”“处理”“操作”等模糊词。
- 先写重要结论，再写原因和下一步。
- 不责怪用户，不用“非法操作”“你输入错了”；写成“端口必须为 1～65535”。
- 按钮尽量 2～6 个汉字；省略号表示还会打开输入流程，例如“导入主题包…”。
- 同一领域词只用一个名称；“启动器”“玩家入口”“微端网关”遵循项目术语。

## 12. 控件使用

- 文本输入只用于自由文本；枚举使用下拉或单选；少量开关使用复选框/开关。
- 表格适合多条同构记录；表格行操作放在上下文命令栏或右键菜单，不在每行堆满按钮。
- 标签页只在同一层级切换内容，不兼任动作按钮。
- 图标必须表达已知语义并配工具提示；不得用来源不明的图标包。
- 禁用控件必须解释启用条件；若当前情境完全无关，优先隐藏。
- 对话框默认按钮和取消按钮必须明确；关闭窗口不得意外提交破坏性动作。

## 13. DPI、主题与无障碍

### 13.1 DPI 和窗口

- MUST 验证 100%、125%、150%、200% DPI。
- MUST 验证 1280×800 和最小 1100×700；SHOULD 验证 1024×768@125% 的关键对话框可用性。
- 文字不得截断核心含义；必要时省略号并提供完整工具提示。
- 图标和自绘控制柄使用 DPI 感知尺寸，不使用固定物理像素截图代替控件。

### 13.2 键盘与辅助技术

- Tab 顺序符合视觉顺序；非交互文字不进入 Tab 序列。
- 自绘画布、图标按钮和状态图标 MUST 提供无障碍名称、角色、值和状态。
- 所有焦点 MUST 有清晰焦点框；不得移除系统焦点提示而不提供替代。
- MUST 支持 Windows 高对比度，不得强制覆盖系统颜色导致不可读。
- 颜色不是唯一信息来源；图标、文本或形状至少补充一种。
- 核心工作流 SHOULD 使用 Narrator、键盘、放大镜和高对比度人工验证。

## 14. Module、Seam 与 Adapter

### 14.1 作者工具外壳 Module

外壳 Module 的 Interface 只负责：当前项目、五模式切换、全局命令、保存/脏状态、状态消息和工作区托管。它不得理解画布命中、吸附、发布签名或区服字段。

### 14.2 设计画布 Module

画布 Module 的 Interface 只暴露：文档、选择、可执行命令、撤销/重做、脏状态、视口状态和变更通知。拖拽、命中、吸附、对齐、锁定与历史属于 Implementation。

### 14.3 Adapter

- `Launcher.ThemeRuntime` Adapter：把启动器主题映射为画布文档并按玩家运行时渲染。
- 后续 FairyGUI Adapter：只有 LEG-07 确认第二种真实文档模型后才建立；不得提前抽象假 Adapter。
- 属性、对象树和视口是画布 Interface 的不同展示 Adapter，不得各自直接修改主题集合。

删除画布 Module 后，如果选择、历史、吸附和状态复杂度会散落回多个窗体，说明该 Module 具有足够 Depth；若外壳仍需操作内部控件集合，则 Interface 过浅，必须先收紧再扩展。

## 15. 自动化与验收门禁

### 15.1 MUST 自动化

1. 主窗口固定五模式及顺序。
2. 默认/最小窗宽下关键区域尺寸与功能可达。
3. 画布客户区坐标、选框和命中区一致。
4. 100/125/150/200% DPI 控件边界与点击区域一致。
5. 锁定无法从各编辑入口绕过。
6. 撤销/重做覆盖所有文档变更。
7. 玩家快照不包含编辑器专属状态。
8. 未保存切换/关闭保护。
9. 生成、签名、历史和回滚既有回归无退化。

### 15.2 MUST 人工/截图验收

1. 1280×800 三栏无重叠、错位、截断和重复导航。
2. 1100×700 次要面板可折叠，主工作表面仍可操作。
3. 无选择、单选、多选、锁定、隐藏、错误和长任务状态均有明确视觉结果。
4. 亮色、高对比度及四档 DPI 至少保存代表性工件。
5. 仅键盘完成：切模式、选对象、移动、改属性、保存和打开预检。

### 15.3 审查分级

- **阻断**：坐标/命中错误、功能不可达、数据或发布风险、关键对比度/键盘失败。
- **应改**：层级混乱、重复导航、主表面被不必要挤压、状态不清、术语不一致。
- **建议**：不影响理解和效率的细节优化。
- **细节**：纯个人偏好，不影响完成判断。

## 16. 禁止事项

1. 禁止为了“现代感”重写 WinForms、引入第二套运行时或第三方商业控件库。
2. 禁止逐窗体复制颜色、字体和间距常量；必须使用集中令牌。
3. 禁止把项目列表、对象树和属性做成多个含义不清的永久并列侧栏。
4. 禁止在主窗口继续追加平级业务标签。
5. 禁止用图片模拟可交互控件或把整个窗口截图当画布背景。
6. 禁止长期在画布上覆盖大块对象名称和调试信息。
7. 禁止只凭截图宣称键盘、DPI、命中区或无障碍通过。
8. 禁止复制参考源码、商业产品资源、图标、品牌颜色或专有布局实现。
