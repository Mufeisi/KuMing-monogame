# 游戏 GUI 动态协议规范

- 状态：协议与服务端会话已实施（`GUI-07/08`）
- 协议事实源：`src/Shared/Shared/CustomGui/CustomGuiProtocol.cs`、`CustomGuiPackets.cs`、`Enums.cs` 与 `Packet.cs`
- 兼容审计：[`../../quality/protocol/PROTO-03-协议与资源兼容矩阵.md`](../../quality/protocol/PROTO-03-协议与资源兼容矩阵.md)
- 语言：中文，代码标识符和协议类型名除外

## 1. 边界

动态 GUI 协议只传递窗口身份、受限显示状态和白名单动作意图。客户端不得提交价格、奖励结果、权威物品属性、次数结论、脚本、反射目标、文件路径或 URL。服务端会话、重放判定、主线程业务验证和客户端状态投影分别由 `GUI-08..10` 实现，本规范不赋予客户端业务权威。

## 2. 包号

| 方向 | ID | 类型 | 职责 |
|---|---:|---|---|
| 客户端→服务端 | 145 | `ClientPackets.CustomGuiAction` | 提交一个绑定窗口身份和递增请求序号的白名单动作意图 |
| 服务端→客户端 | 275 | `ServerPackets.CustomGuiOpen` | 打开指定签名 GUI 版本并给出有期限的初始状态 |
| 服务端→客户端 | 276 | `ServerPackets.CustomGuiStateDelta` | 用严格递增状态修订投影有界增量 |
| 服务端→客户端 | 277 | `ServerPackets.CustomGuiActionResult` | 返回动作接受、拒绝、过期、陈旧或非法结果 |
| 服务端→客户端 | 278 | `ServerPackets.CustomGuiClose` | 以稳定原因关闭或失效窗口 |

`wire-v1` 的 ID `0..144` 与 `0..274` 保持冻结；上述包属于只追加新 ID 的 `gui-wire-v2` 扩展，不改变旧包布局。

## 3. 身份与状态

打开、增量和动作共同绑定非零 `WindowInstanceId`、`DocumentId`、正数 `DocumentRevision`、正数 `PackageSequence` 与非空 128 位 `SessionNonce`。动作另带非零 `RequestSequence`；打开带绝对过期时间和非零 `StateRevision`；增量带非零后继状态修订。服务端已基于这些字段实现玩家级会话和重放保护。

首版状态类型固定为文本、布尔、整数、进度、有界列表、有界物品槽集合、按钮可见和按钮可用。物品槽只下发稳定 `ItemId`、显示资源/名称、数量与可用状态；客户端回传时只能提交 `ItemId`，服务端必须重新校验所有权和业务条件。

动作类型固定为 `CloseWindow/OpenWindow/SwitchPage/SubmitText/SubmitSelection/SubmitItems/RequestAction`。文本、选择和物品载荷按动作类型互斥：提交选择至少一项且不能夹带文本/物品；提交物品至少一项且不能夹带文本/选择；其他动作不能夹带三类输入。

## 4. 强制上限

| 范围 | 上限 |
|---|---:|
| 打开/增量载荷 | 60 KiB |
| 客户端动作载荷 | 16 KiB |
| 结果/关闭载荷 | 8 KiB |
| 状态绑定 | 128 项，绑定键唯一 |
| 单个/全部列表项 | 64 / 256 |
| 单个/全部物品槽 | 32 / 64 |
| 选择/提交物品标识 | 64 / 32，均不得重复 |
| 输入文本/状态文本/结果消息 | 2048 / 2048 / 512 字符 |
| 文档、动作、绑定和资源标识 | 128 字符 |

字符串使用明确的 `UInt16` UTF-8 字节长度并由严格 UTF-8 解码器读取；集合使用 `UInt16` 计数，但必须先通过更小的业务上限。未知版本、未知枚举、无效布尔、重复键、重复标识、截断、尾随数据、无效进度、无效物品槽及动作/载荷不匹配均失败关闭。

## 5. 稳定诊断

- `GUI07-PROTOCOL-001`：身份、状态或动作结构无效。
- `GUI07-LIMIT-001`：字段、集合、汇总项或总载荷超限。
- `GUI07-ENUM-001`：未知动作、状态、结果或关闭原因。
- `GUI07-FRAME-001`：截断或尾随数据。

## 6. 服务端会话门卫

每个 `MirConnection` 拥有独立 `CustomGuiSessionController`，只在 `Game` 阶段且存在真实 `PlayerObject` 时允许开窗或处理动作。窗口实例和随机数由服务端使用加密随机源生成；单玩家最多八个活动窗口，最长有效期三十分钟。同一文档新开时先关闭旧实例，签名包序列变化时关闭不匹配实例。

动作序号必须从 `1` 开始严格连续递增。小于等于已消费序号视为重放，大于下一序号视为乱序；两者都不推进游标。随机数不匹配、文档/修订/包序列不匹配、过期、非游戏阶段或不存在会话均拒绝。自然过期、客户端关闭、文档替换、版本切换、登出和断线均有明确清理路径。

稳定会话诊断为 `GUI08-SESSION-*`，未登记业务动作和处理器故障分别为 `GUI08-ACTION-UNHANDLED`、`GUI08-ACTION-ERROR`。会话门卫通过只代表请求身份可信；若 `GUI-09` 业务处理器尚未登记，服务端明确拒绝而不是回报业务成功。

运维停用复用既有持久化 `Activities` Kill Switch。停用后拒绝新窗口，并在连接主循环以 `Invalidated` 原因关闭现有动态窗口；不增加第二份开关事实源。

## 7. 回滚

回滚 `gui-wire-v2` 必须先通过既有 `Activities` Kill Switch 停止新开窗口并失效现有会话，再按独立提交逆序回滚；`wire-v1` 清单和旧包号不需要修改。进入生产兼容窗口后，不得复用 ID `145/275..278` 表达其他语义。
