## 当前结论

1. CHM 中共有 1,012 个目录主题；其中动作、检测和触发分类页共 540 个。页面数不能作为命令数或兼容率分母。
2. 首轮正文结构抽取得到 453 个去重命令/触发候选；后续按独立语义卡补入变量、真实语料高频命令、特殊触发、客户端事实和安全替代，当前共 496 项且无 `?`。后续发现新的复合页面时仍按独立语义卡增量补入。
3. 指定真实项目包含 2,348 个 `.cs` 内容模块，不是 2,348 个原生 TXT。其中 121 个模块直接构造 `TextFileDefinition`，原始 `AddLine` 调用仅 54 行；其余内容主要通过类型化注册表和 `ScriptApi` 表达。
4. 当前 `NPCSegment` 已识别 `CHECKGOLD`、`CHECKPKPOINT`、`RANDOM`、`GIVEGOLD`、`GIVEITEM`、`TAKEITEM`、`GIVEEXP`、`LOCALMESSAGE` 等旧 DSL 命令，`ScriptApi` 也有多项对应领域方法；在参数、边界、失败行为和副作用测试完成前，这些事实不能直接升级为 A/B。
5. 翎风正文中的金币调整命令为 `GOLDCOUNT (=|+|-) 金币值`，而真实语料和现有解析器高频使用 `CHECKGOLD`、`GIVEGOLD` 等命令。它们不是同一语法签名，后续必须分别核对并提供别名或迁移说明。
6. 当前已有独立物理 TXT Provider、组合来源、快照重载、统一变量、高频命令包、登录/升级触发、战斗/物品/怪物触发安全子集和受控高风险替代；默认关闭，启用后只读取白名单目录并执行路径、编码、大小、命令和引用校验。D/E/X 条目不属于本版本发布承诺，因此仍不能据此声称完整兼容翎风全部能力。

## 特殊触发差异

- `@ATTACKDAMAGE`、`@STRUCKDAMAGE` 与 `CHANGEDAMAGEVALUE` 已按类型化伤害请求接入；最终伤害归零时显式取消，C# Handler 存在时不重复执行 TXT。
- `@ATTACK`、`@STRUCK` 只对应物理伤害结算后的只读结果，不冒充魔法标签。
- `@PICKUPITEMEX` 只覆盖玩家自身成功拾取；灵物代拾暂未桥接。
- `@KILLMON` 按怪物 `EXPOwner` 解析玩家或英雄主人；`@M2DROPITEM` 每个掉落批次触发一次且不支持逐物品改名改色。因此这五项保持 C，不标成完全等价。

## 已识别的审计风险

- 部分 HHC 路径包含 `%20`，读取时必须 URL 解码；另有目录条目指向快照中不存在的 HTML 文件。
- `H.Command` 表示英雄对象上下文，不能仅删除前缀后认定与人物命令完全等价。
- “传奇基础脚本命令详解”等资料页在单页中说明多条基础命令，必须拆分为独立语义卡。
- 真实项目已大量迁移到结构化 C#。扫描传统 DSL 首词会低估真实业务用法，扫描 API 方法名又不能自动证明翎风语义一致。
- 自动抽取不能直接证明兼容；当前条目虽已完成正文判定并消除 `?`，仍只有实现、测试和说明书证据齐全的条目才能标为 A/B/C。

## 回滚与更新规则

清单只用于审计，不被运行时读取。错误标注的回滚方式是恢复 CSV 对应行并重新运行清单门禁；不得通过修改运行时语义来迎合清单。每次脚本或 CHM 快照变化后必须重新计算摘要并复核受影响条目。
