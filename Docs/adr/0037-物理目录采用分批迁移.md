# 物理目录采用分批迁移

- 状态：已接受
- 日期：2026-08-12
- 决策人：项目所有者
- 关联任务：ENG-12
- 取代：[`ADR-0036`](0036-暂不执行物理目录重排.md)

## 背景

首轮工程治理已经解决逻辑模块、所有权、开发入口、CI 和文档事实源，但仓库根目录仍平铺客户端、服务端、启动器、微端、编辑器、测试、工具、第三方二进制和本地产物目录。Windows 文件浏览器中需要同时辨认二十余个源码目录与 `artifacts`、`Build`、空目录及本机秘密目录，根目录可读性仍然较差。

2026-08-12 复核确认：

- 磁盘与主解决方案均为 30 个工程，集合一致性已有 CI；
- Markdown 链接、协议清单、Windows 构建、通用测试和 Android AOT 均有自动门禁；
- 首轮产品与治理分支已经收口，`main` 干净；
- 根目录 `artifacts` 约 2.4 万文件、`Build` 约 7200 文件，另有只含 `bin/obj` 的未跟踪目录，显著放大导航噪声；
- 用户明确要求根目录结构直接可读，并授权渐进迁移和完整验证。

## 决定

采用分批、可回滚的物理目录迁移，使根目录最终只保留稳定入口和仓库级配置。目标结构为：

```text
src/
  Clients/
  Server/
  Launcher/
  MicroGateway/
  Editors/
  Shared/
Tests/
  Base05.Tests/
  ShareProtocolCompat/
eng/
  WindowsIntegration/
Tools/
third-party/
legacy/
docs/
build/
artifacts/            # 本地产物，Git 忽略
.github/
```

仓库级文件如 `README.md`、`AGENTS.md`、`CONTRIBUTING.md`、`Directory.Build.props`、`global.json`、解决方案、过滤器和资源清单继续保留在根目录。

新分类目录采用英文小写；既有 `Tests/`、`Tools/` 保留 Windows 兼容大小写。现有工程目录名、程序集名和命名空间在纯搬迁阶段保持不变，避免把路径迁移与代码重命名混为一个变更。

## 迁移批次

1. 根目录卫生：明确本地产物、运行秘密、受控构建资源和历史资料边界；不删除不可恢复内容。
2. 低耦合开发设施（本地验证完成，等待主线门禁）：保留 Windows 兼容的 `Tests/`、`Tools/`，将专项验收工程 `WindowsIntegration` 迁入 `eng/WindowsIntegration/`；不执行纯大小写目录改名，也不把专项工程混入通用测试树。
3. 外围模块：编辑器、控件、补丁网站、第三方二进制和历史资料迁入 `src/Editors/`、`legacy/`、`third-party/`、`docs/archive/`。
4. 产品外围：Launcher 与 MicroGateway 迁入 `src/Launcher/`、`src/MicroGateway/`。
5. 产品核心：客户端、服务端与 Shared 迁入 `src/Clients/`、`src/Server/`、`src/Shared/`。
6. 收口：消除旧路径引用，更新模块地图、CODEOWNERS、开发入口和最终目录说明。

每批必须使用独立分支、提交和 PR；上一批合并且最新 `main` 必需检查通过后才能开始下一批。

## 不变量

- 30 个有效工程必须全部保留并进入主解决方案；不得借搬迁删除“看似无用”的工程。
- 程序集名、命名空间、协议、Schema、线程模型、资源版本、签名身份和运行行为保持不变。
- `Shared/Packet.cs` 等高风险事实源只移动，不修改内容。
- 本地密钥、数据库、授权资源、运行配置和不可恢复制品不得删除、覆盖或提交。
- `Build/Mobile/BootstrapRepo/Packages/core-startup.zip` 及 sidecar 属于受控资源，迁移时必须保持资源清单契约和摘要。
- 历史 Evidence 不批量改写；它们保留执行时路径语境，当前入口文档负责指向新路径。

## 每批验证

至少执行：

1. `git diff --check` 与 Markdown 相对链接检查；
2. 磁盘 `.csproj` 与主解决方案工程集合一致性；
3. 受影响 `.slnf` restore/build；
4. 受影响测试与协议/资源漂移检查；
5. 远端三项必需检查：Windows、通用测试、Android Release arm64 AOT；
6. 合并后最新 `main` 再次通过同一门禁。

涉及发布工具、资源或签名路径的批次额外执行相应专项测试，不以普通编译代替。

## 回滚

每批仅包含路径移动及必需引用修正，可通过回退该批合并提交恢复。不得在同一批混入业务功能、依赖升级、大规模格式化或命名空间重命名。

本地产物若需要调整位置，先复制或保留原目录，验证新入口后再由用户明确授权清理；Git 迁移不以删除本机产物作为完成条件。

## 后果

迁移期间部分路径会逐批变化，历史命令不能保证继续有效；当前 README、开发者指南、解决方案和脚本必须同步。最终根目录的分类会直接表达模块关系，但模块深度仍由接口和实现决定，不能以目录整齐替代 ENG-08 的渐进深模块化。
