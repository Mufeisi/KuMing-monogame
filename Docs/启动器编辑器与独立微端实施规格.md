# 启动器编辑器与独立微端实施规格

> 状态：2026-08-11 代码候选实现与本机自动化已完成；外部物理验收尚未全部关闭。本规格与相关 ADR 已纳入任务分支，但在第 10 节所列外部证据完成前，不宣称 GATE-L5 完整关闭。

## 1. 目标

交付一套面向普通 GM 的 Windows 离线工具链，使 GM 不依赖域名、HTTPS、网站、数据库、源码、Visual Studio 或 .NET SDK，即可完成启动器个性化、远程区服维护、单一玩家 EXE 生成、微端资源准备和独立微端部署。

玩家只主动下载并运行一个 EXE。入口自动发现已有客户端；没有客户端时只安装启动核心，进入游戏后通过微端按需获取资源。生产环境默认将游戏服务器和微端服务器分机部署。

优先级固定为：GM 操作简单、部署广泛、玩家操作少、失败可恢复；不得为了实现本规格重写现有 Bootstrap、补丁、微端客户端、协议序列化或渲染接缝。

## 2. 系统边界

### 2.1 GM 编辑器

Windows 本地桌面程序，离线可完成项目、主题、区服、公告、客户端发行、签名和工件生成。一个编辑器可管理多个相互隔离的 GM 启动器项目。

### 2.2 玩家入口

由预构建模板生成的单一 Windows EXE，内嵌项目身份、远程发布源、信任公钥、内置主题及最低可用配置快照。文件重命名不得改变行为，不依赖同目录 INI、图片或主题文件。

### 2.3 独立微端网关

从当前游戏服务端内嵌微端提取出的独立系统，复用现有 `/api/file`、`/api/libheader`、`/api/libimage`、`/api/sound`、HTTP Range、资源读取和客户端协议。默认运行在独立微端服务器；现有服务端内置模式只保留兼容和测试用途。

### 2.4 启动器发布源

微端网关默认通过公开只读 `/launcher/` 路径托管签名后的主题、公告、区服清单和玩家入口更新；外部静态网站或 CDN 是可选替代。公网接口不得提供写配置、启停服务或清理缓存能力。

## 3. 领域与配置模型

### 3.1 GM 启动器项目

每个项目独立拥有：

- 项目标识和品牌元数据；
- 内置主题、远程主题及模板源素材；
- 区服分组、区服条目和区服状态；
- 默认微端入口、可选备用入口及区服覆盖；
- 客户端发行与启动核心设置；
- 玩家入口普通/强制更新策略；
- 当前与下一把签名密钥、公钥信任和恢复包状态；
- 发布源、不可变版本历史及回滚记录。

项目文件不得保存明文密码、服务端保护秘密或玩家数据。

### 3.2 区服目录

区服目录支持一级可选分组。区服至少包含稳定标识、显示名称、排序、游戏主机、游戏端口、运营状态、是否可进入和可选微端覆盖。

第一版状态固定为正常、火爆、推荐、新区、维护、即将开放和隐藏。维护与即将开放默认禁止进入并显示 GM 提示；隐藏条目不下发给玩家。状态由 GM 发布，不宣称表示实时人数、延迟或自动探测结果。

区服选择模式由 GM 在主题中固定为下拉式或侧边栏展开式，玩家不能切换。两种模式消费同一份区服目录，不改变连接语义。

### 3.3 主题

主题使用固定逻辑画布并随 Windows DPI 等比缩放。首版提供经典兼容、紧凑下拉和宽屏侧边栏三套完整模板。

固定功能控件可以调整位置、尺寸、显隐、字体、颜色、透明度、背景和图片，但不能新增任意脚本或未知控件。按钮仅绑定安全动作白名单，包括开始游戏、选区侧栏、游戏设置、账号相关网页、官网、充值、客服、公告、检查更新、修复客户端、选择客户端位置、最小化和关闭。

图片输入支持 PNG、BMP、JPG；首版不支持 GIF 或视频。发布时保留源素材，BMP 默认无损转 PNG，透明素材保持 PNG，照片背景可保持 JPG。按钮默认从一张基础图派生悬停、按下和禁用状态，同时允许逐状态覆盖。

主题按远程有效版本、上次有效主题快照、内置主题的顺序整套选择，禁止混用不同版本素材。

### 3.4 公告与玩家设置

公告默认由编辑器维护，支持多篇、置顶、发布时间、图片及 HTTP/HTTPS 链接；外部网页为可选模式，失败时回退内置公告。远程内容不得执行本地程序、脚本或命令行。

玩家设置能力由程序固定实现，主题只改变外观、位置和显隐。至少包含动态分辨率列表、窗口化、全屏、FPS 限制、窗口置顶、自动开始、音乐与音效音量、客户端位置、微端缓存、客户端修复和高级日志；不得保存明文账号密码。

### 3.5 已签名启动器版本

每个发布版本包含单调序列、最低兼容玩家入口版本、主题、公告、区服目录、文件摘要和签名。编辑器自动完成签名与复验，不要求 GM 执行签名命令、申请域名或配置 HTTPS。

未签名、摘要不一致、未知密钥、低序列或不完整版本整体拒绝。回滚通过以更高序列重新发布历史内容实现，不倒退客户端防降级状态。

## 4. GM 工作流

### 4.1 创建与导入

新建项目提供可跳过的向导，覆盖品牌、客户端目录、交付模式、游戏与微端入口、模板、发布源、密钥恢复和工件生成。跳过后创建安全默认项目，缺失必填项只在生成或发布时集中阻止。

编辑器支持只读导入现有客户端目录、`Mir2Config.ini` 和远程区服清单。导入前显示映射预览，未知字段明确提示，不修改原目录，不把敏感明文写入项目。

### 4.2 编辑与预览

GM 可离线编辑主题、区服、公告、设置面板外观和品牌信息，并在下拉/侧栏模式及 100%、125%、150%、200% DPI 下实时预览。发布前自动检查文字截断、控件越界、点击区域重叠、缺失素材和非法链接。

### 4.3 生成工件

一次项目生成可以输出：

- 可直接分享到网盘或群文件的单一玩家 EXE；
- 独立微端网关部署包；
- 不含私钥的离线部署包；
- 带独立恢复密码的项目恢复包；
- 可交换但不含秘密的主题模板包。

GM 可设置 EXE 文件名、图标、产品名称、文件说明、公司、版权、文件版本、产品版本、窗口标题和任务栏名称。代码签名证书为可选增强，不是生成门槛。

### 4.4 发布与回滚

每次发布创建不可变目录；全部文件上传并复验后才原子切换当前版本。中断继续服务旧版本。编辑器显示版本、时间、备注和内容差异，并可一键回滚。

编辑器离线时可生成签名部署包，通过远程桌面、移动介质或其他方式复制到联网服务器导入。目标服务器不需要源码、编译环境或完整编辑器。

## 5. 玩家流程

1. 玩家从网盘、群文件或其他渠道下载一个 EXE。
2. EXE 位于有效客户端目录时原地复用；否则自动查找已有客户端。
3. 找到唯一客户端时复用；存在多个候选、目录不可写或空间不足时才要求选择。
4. 没有客户端时显示一次位置、启动核心大小和可用空间确认，将正式入口安置到稳定游戏目录；再次运行原下载文件时转交正式入口，原文件不删除。
5. 按远程有效配置、上次有效缓存、EXE 内嵌保底的顺序加载主题与区服。
6. 微端模式只要求启动核心完成后允许进入游戏，其他资源由当前急需下载和后台推荐包补齐。
7. 正常下载只显示非阻断状态；自动重试失败后主入口切换到可选备用入口，主备均失败时才提示玩家。
8. 玩家不能主动切换为完整客户端模式，也不提供“下载全部资源”入口。
9. 普通入口更新后台下载并在游戏退出或下次启动时应用；强制更新仅用于安全或兼容门槛。游戏运行期间不得替换 EXE，失败保留旧版。

## 6. 独立微端网关规格

### 6.1 部署与宿主

网关默认以可直接双击的 Windows GUI EXE 运行，支持最小化托盘、随 Windows 启动和一键注册 Windows 服务。GUI 与服务复用同一核心、配置、状态和日志。

一个网关实例只管理一套完整客户端资源库；同一发行体多个区服共享默认入口，特殊区服可以覆盖。不同客户端使用独立实例和端口。

正式部署必须支持 HTTP、IP＋端口；HTTPS 是可选增强。网关提供可撤销的一键 URLACL、Windows 防火墙、端口占用检查和本机健康验证。路由器映射和云安全组只提示，不默认修改。

### 6.2 资源库与扫描

GM 将完整客户端上传到微端服务器并指定客户端目录。网关启动时全量扫描，运行期监视新增、修改和删除；文件稳定后合并生成新索引，成功后原子切换，失败沿用旧索引。提供手动重扫和低频完整核对。

### 6.3 缓存

使用自动限额的内存与磁盘两级缓存。GM 只配置缓存目录和容量上限；达到上限自动淘汰，资源变化只使相关条目失效。缓存不得修改或删除完整资源库，损坏后可自动重建。

### 6.4 连接与管理边界

默认微端入口在项目级配置，可增加一个同版本、同签名身份的备用入口。客户端仅在主入口连续失败后按会话切换，下次启动重新优先主入口。

编辑器自动生成并同步微端访问用户与 Code：服务端材料导入 Windows 受保护存储，玩家侧访问材料嵌入专属入口并由运行时读取，不要求 GM 手工编辑配置。由于启动核心在登录前下载，玩家侧材料不能被宣称为不可提取的真正秘密，只用于基础访问控制、盗链门槛和限流标识。

公网只提供玩家资源和有限只读健康、版本、资源状态检测。目录、端口、Code、缓存、启停和清理只能通过本机 GUI、Windows 服务管理、远程桌面或签名配置导入完成。

## 7. 分阶段实施与退出条件

### 阶段 1：独立微端网关

范围：从游戏服务端提取现有微端处理为可复用深模块，交付独立宿主，保留内置兼容模式。

退出条件：

- 独立网关可在与游戏服务器不同的 Windows 机器启动；
- 当前玩家客户端无需协议修改即可通过全部现有微端路由获取资源；
- `/api/file` Range、图库头、单图、声音、鉴权和 Kill Switch 行为具有回归验证；
- 独立网关不依赖游戏世界 `Envir` 生命周期；
- 服务端内置模式仍可运行；
- 交付可运行 EXE、专项测试结果和双机验证记录。

### 阶段 2：主题运行时

范围：主题模型、经典迁移、两种区服模式及完整回退。

退出条件：

- 经典模板与现有启动器截图达到可接受视觉一致性；
- 紧凑下拉和宽屏侧栏均可读取同一区服目录并正确启动所选区服；
- PNG/BMP/JPG、按钮自动四态和高级覆盖可见；
- 多档 DPI 无越界、重叠或错误点击区域；
- 远程、缓存、内置主题回退均通过故障测试；
- 交付可运行玩家入口、截图和专项测试结果。

### 阶段 3：GM 编辑器核心

范围：多项目、可跳过向导、现有项目导入、主题/区服/公告编辑、预览和网关部署包。

退出条件：

- 编辑器断网时可完成新建、导入、编辑、预览和保存；
- 区服分组、状态、两种模式和设置面板可视化配置有效；
- 导入过程不修改原客户端，未知字段与秘密处理符合规格；
- 能生成可在另一台机器启动的微端部署包；
- 交付编辑器 EXE、示例项目、预览截图和验证结果。

### 阶段 4：单一玩家入口

范围：预构建模板生成、品牌字段、自动安置、客户端发现、启动核心和自更新。

退出条件：

- GM 机器无需源码或 SDK 即可生成一个玩家 EXE；
- EXE 在无任何同目录辅助文件时启动，重命名后仍可用；
- 下载目录首次运行、已有客户端复用、多候选和空间不足路径均通过；
- 没有客户端时只安装启动核心即可进入登录流程；
- 普通/强制更新、运行中不替换和失败回退通过；
- 交付可分享 EXE、生成日志和端到端录屏或截图。

### 阶段 5：发布体系

范围：自动签名、密钥恢复、发布源、离线部署、版本历史、回滚和主备入口。

退出条件：

- 正确签名、篡改、未知密钥、低序列和不完整版本全部有测试；
- 当前/下一密钥轮换与加密恢复包可演练；
- 发布中断不影响当前线上版本；
- 一键回滚通过更高序列恢复旧内容；
- 微端 `/launcher/`、外部静态源和离线导入至少分别完成一次验证；
- 交付签名发布版本、回滚证据和恢复演练记录。

### 阶段 6：微端运维完善

范围：GUI/服务双宿主、自动扫描、两级缓存、一键网络配置、状态与诊断。

退出条件：

- GUI 与 Windows 服务使用相同配置和状态；
- 上传中文件不进入有效索引，原子切换和失败沿用旧索引通过；
- 缓存限额、淘汰、局部失效、损坏恢复和不删除资源库通过；
- URLACL、防火墙配置及撤销可复核；
- 公网写管理接口不可用，只读状态不泄露 Code、路径或秘密；
- 交付网关运维 EXE、服务安装验证、压力与故障恢复结果。

## 8. 明确不做

- 第一版不支持 GIF、视频背景、任意脚本和任意新增控件；
- 不提供实时在线人数、客户端延迟或自动区服探测状态；
- 不向玩家提供主动下载全部资源或交付模式切换；
- 不要求公网 HTTPS、域名、网站、IIS、Nginx 或云后台；
- 不提供公网写管理、远程启停、远程清缓存或远程修改 Code；
- 不在公开清单、模板包、部署包或项目普通配置中保存私钥和明文秘密；
- 不重写现有 Bootstrap、补丁、微端客户端协议、游戏协议、渲染接缝或 Shared/Packet；
- 不在本轮扩展 Android/iOS 启动器编辑能力；
- 未经明确确认，不把候选实现宣称为完整交付，不跳过外部物理验收结论。

## 9. 完成定义

每阶段完成必须同时具备：可运行工件、与阶段风险匹配的自动化或集成验证、中文运行证据、与本规格逐项对照的验收结果。只提交框架、计划、界面空壳、分析报告或未运行代码均不算完成。

语言要求：交流、文档、状态、发布说明和提交信息使用中文；代码标识符、命令和原始错误保留英文。
