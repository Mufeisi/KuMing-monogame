# 执行纪律与防走偏铁律（Codex / Agent 必读）

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-08-05 |
| 适用 | 所有在本仓库执行任务的 Agent（Codex / Claude / 其他），尤其全量、多阶段任务 |
| 来源 | 历史教训：Codex 在全量任务中反复犯"造机器代替干活"的错——51k Core 重写 → 造 Roslyn 分析器找文件 → 造金图基建；产出"管理迁移的机器"而非迁移本身。本铁律由这些教训提炼 |
| 配套 | 根目录 `AGENTS.md`（浓缩版）；PRD 的 GATE 门禁与任务编号；架构报告的 ADR/技术边界 |

---

## 0. 一句话总纲

> **任何任务，默认交付"能跑的东西"（代码/diff/截图/通过的测试），不交付"关于怎么干活的东西"（分析器/矩阵/迁移计划/审核报告/工具）。**
>
> 判断标准只有一句：**今天产出的东西，用户能不能直接看到、直接用到？**
> 能 → 继续；不能 → 停下来重新想，不要接着造。

---

## 1. 禁止造机器（最高优先级铁律）

**任何"我先造个 X 才能继续干活"的冲动，默认禁止，除非任务简报里显式批准。**

典型违规（历史真实发生）：

| 想干的事 | 正确做法 | 禁止做法 |
|---|---|---|
| 找"要改哪些文件" | `grep`/`rg` 直接搜 | 造 Roslyn 分析器扫描全库 |
| 算协议差集（29 个包） | 一次性脚本，跑完就扔 | 先造 wire manifest 工具 |
| 追踪任务进度 | 用 PRD 的编号勾选 | 造"任务管理面板" |
| 验证序列化一致 | 直接 diff + 写测试 | 造 golden 生成框架 |
| 重构巨型类 | 提取一个真边界模块 + 测试 | 先造"耦合度分析器" |
| 迁移 net10 | 直接改 TFM 构建 | 造"迁移影响评估工具" |

**规则**：
1. 干活需要的工具，如果超过 30 行脚本才能完成 → 先在简报里说明"要造 X 工具"，经确认后才做。
2. 造的工具如果是"一次性"的，跑完即弃，禁止沉淀成工程。
3. **工具/矩阵/报告本身永远不是任务目标**，只是可能的手段。

---

## 2. 当前唯一目标（范围门禁）

**每阶段只有一个目标 = PRD 对应 GATE 的退出条件。超出的一律不做。**

- 发现"顺手就能改"的 bug → **记入 backlog，不改**（除非它阻塞当前目标）。
- 发现"更好的架构" → **记入架构报告候选，不实施**（架构变动必须过 ADR）。
- 下一阶段的事 → **一律不做**，即使看起来"反正要做"。
  - 反例：P0 做 net10 迁移时，顺手把 P2 的 Argon2id 一起改了。
  - 正例：P0 遇到密码哈希弱，记入 SEC-01 backlog，继续迁移。

---

## 3. 完成定义 = 工件，不是"计划被批准"

每个子任务必须产出**可验证的工件**，形式只能是下列之一：

| 工件类型 | 例子 | 验收方式 |
|---|---|---|
| 代码/diff | 改好的 csproj、修复的 bug | `git diff` 可看 |
| 运行输出 | 构建成功、测试通过 | 命令输出贴回 |
| 截图/录屏 | 渲染效果、UI 界面 | 图片文件 |
| 对比数据 | 优化前后 FPS/耗时 | 同一场景前后数字 |

**禁止作为任务完成**：写了分析报告、画了架构图、列了清单、做了"研究"，但没有对应的代码/截图/数据。

**例外**：架构报告/PRD 本身的编写任务（本铁律不适用），但这类任务占比必须 < 20%。

## 4. 任务简报固定模板

> 每个子任务开工前，先写出这个简报。**写不出"完成定义"的任务，说明任务本身定义不清，先回去拆。**

```
【任务简报】
目标（一句话，动词开头）：________________
语言：本任务全部输出中文（英文仅限代码标识符/命令/报错原文）
范围：
  做：________________
  不做：________________
方法约束：
  必须用：________________
  禁止：________________
预估时间：≤ ____ 小时
完成定义（必须产出的工件）：
  1. ________________（代码/diff）
  2. ________________（截图/输出）
时间预算：超过预估 2× → 停下报告，不继续
```

## 4a. 语言纪律（中文保持）

> 本仓库全部交流/文档/状态报告/commit message 一律中文。这是**硬规则**，不是偏好。

- **为什么**：长会话 + 大量英文工具输出（构建日志/git/报错）会触发"语言跟随效应"——上下文里英文占比高，模型输出语言被带偏，早期中文指令在上下文压缩（英文摘要）后失去锚点，于是越到后面越偏英文。
- **规则**：
  1. 输出默认中文；英文仅限代码标识符、命令、报错原文、不可翻译的技术名词。
  2. **整段英文输出 = 违规**，触发停止条件（见 §5 停止条件 8），停下用中文重发，不继续。
  3. 任务简报"语言"字段必填。
  4. 面对大段英文工具输出时，主动用中文转述关键信息，不要原样堆积进上下文。
- **控制手段**：语言规则已在 AGENTS.md 铁律、任务简报模板、每日工件检查三处锚定；会话中途若发现漂移，立即停下以中文重新声明，不"将就着继续"。

## 5. 时间预算与打转报警

**硬性停止条件（任一命中，立即停下报告，不继续）**：

1. 连续 3 轮输出都是"分析/计划/审核"，没有任何代码改动。
2. 开始"造工具"才能继续（见 §1）。
3. 一个子任务超过预估时间 2× 仍无工件产出。
4. 同一个问题连续 2 次尝试无进展（不是难，是在打转）。
5. 当天产出里"过程资产"（分析/计划/矩阵）数量 ≥ 工件数量。
6. 出现"我需要先造 X 才能继续"的说法。
7. 把一个已完成的功能当"没做"重新做（重造轮子）。
8. **输出语言漂移为英文**（整段英文输出，见 §4a）：立即停下，用中文重发；若反复漂移，压缩上下文或拆分任务。

**停止后的动作（按顺序）**：
1. 停下，不继续打转。
2. 把当前状态、已产出、卡点、尝试过什么写成一页报告。
3. 给出 2~3 个下一步选项 + 各自的预估，交给用户拍板。
4. **禁止自行决定"换个更大的工具再来一次"。**

**升级层级规则（谁拍板什么）**：

| 问题类型 | 谁决定 | 禁止 |
|---|---|---|
| 产品/门禁/定义级（验收标准、阶段范围、资源策略） | **用户** | agent 自行改定义或硬试 |
| 技术实现选择（用什么摘要模型、A/B 方案） | **agent 自定并记录** | 把 1/2/3 类技术选项抛给用户 |
| 技术实现与既有约束冲突 | 先查 ADR/铁律，再定 | 私自改红线 |

- 把技术实现选择抛给用户 = 把该自己干的活推给用户 = 走偏。除非选项间有用户才能知道的偏好/成本约束。
- 停下来报告时，先自问：**这是"怎么实现"还是"定义是什么"？** 前者自己定，后者升级。

**定义升级出口（新增）**：
- 当"验收标准在当前基建下结构性不可满足"时（例如：11GB 外部资源仅存本机、仓库无镜像、无 CI → "裸 clone 可重建"无法验证），**禁止硬试**。
- 动作：把"当前验收标准为何不可满足 + 建议的重新定义（拆成可完成项 + 独立后续项）"写成一段，升级给用户，经确认后改定义。
- 已完成多次全流程验证仍失败，且修复点是小改动 → **先质疑定义，再考虑重跑**（见下面"验证成本分层"）。

**验证成本分层（新增）**：
- 单次验证成本 > 30 分钟（或 > 1GB 复制）的任务，**禁止为小改动重跑全流程**。
- 分层：
  - **快内环**（每次改动都跑）：局部编译、单元测试、静态检查、小范围 Validate——分钟级。
  - **慢外环**（只在阶段末/关键节点跑）：全量 Acquire、11GB 复制、完整发布构建——允许长耗时。
- 小改动 → 只跑快内环；慢外环只在"阶段验收"或"明确定义的重试验证"时跑，且每次重跑前**先书面说明为什么这次值得跑**（不是"再试一次"）。
- 反例：改一行 guard → 重跑 36 分钟全量 acquire（历史真实发生，已卡死两轮）。
- 正例：改一行 guard → 跑局部校验（分钟级）→ 阶段末统一跑一次完整验收。

## 6. 每日工件检查（每个工作阶段结束时）

```
【每日工件检查】
今天产出的用户可见工件：
  1. 可运行代码/diff：____
  2. 对比截图：____
  3. 通过的测试：____
今天的过程资产（分析/计划/矩阵/审核）：____（应 ≤ 1 项）
结论：过程资产 > 工件 → 明天必须换策略，不许继续"研究式"推进。
语言：今天全部输出是否中文（除代码/命令/报错）？____ 若否 → 记录漂移点，明天按 §4a 重锚定。
```

## 8. 边界敏感（技术红线速查）

- **协议**：`Shared/` 是唯一事实源；改协议 = 改 Shared + 更新 manifest + 跑兼容测试 + 同步移动端。禁止在 `Share/` 副本改。
- **主循环**：服务器单线程 + 怪物分线程。玩家状态只主线程写；跨线程走 `InvokeOnMainThread`。
- **脚本**：脚本只做旁路 Hook + 数据定义 + 活动规则层；禁止脚本写核心引擎/直接写持久化。
- **渲染**：PC 走 `DXManager`，移动走 `SpriteBatchStack`；禁止绕过接缝直连 D3D/GPU。
- **迁移**：txt→C# 逐批过 `NpcScriptCoverage`；DB 改表必须新增 `SchemaMigration`。
- **运行时**：发布物禁止依赖 Preview SDK/Runtime/NuGet；未过 GATE 的阶段不许做下一阶段的事。

---

## 9. 与 PRD/架构报告的关系

- PRD 的 **GATE-P0..P5** 是阶段硬门禁：GATE 未过，禁止进入下一阶段。
- 架构报告的 **ADR** 是决策依据：架构变动必须先过 ADR，禁止"顺手改架构"。
- 本铁律是**执行层约束**：约束"怎么做"，不改变 PRD"做什么"。
