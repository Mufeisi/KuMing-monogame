## 1. 环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11；通用 `net10.0` 测试可在 Linux CI 运行 |
| .NET SDK | `global.json` 固定的 10.0.200 |
| IDE | Visual Studio 2022，安装 .NET 桌面开发；Android 工作需对应 .NET workload、JDK 和 Android SDK |
| Shell | PowerShell 7，命令使用 `pwsh -NoProfile` |
| 外部资源 | 完整 PC/Android 运行需要授权资源；源码构建和多数测试不需要完整资源 |

环境检查：

```powershell
dotnet --version
dotnet workload list
pwsh -NoProfile -File Tools/ResourceBaseline.ps1 -Action Validate -Scope Repository
```

`dotnet --version` 必须与 `global.json` 一致。`Scope Repository` 只验证仓库内基线，不获取或修改外部授权资源。

## 2. 选择工作区

| 文件 | 用途 | 当前项目数 |
|---|---|---:|
| `Legend of Mir.sln` | 全部工程及逻辑架构视图 | 30 |
| `LyoCrystal.Windows.slnf` | 现有 Windows 发布构建基线 | 10 |
| `LyoCrystal.Server.slnf` | 服务端核心、Windows 宿主及相关基础测试 | 5 |
| `LyoCrystal.Launcher.slnf` | 启动器、微端、打包工具和相关 Windows 集成测试 | 12 |

Android 与 iOS 使用各自 `.csproj`。iOS 目标只在显式启用时求值，不属于 Windows/Android 门禁。

`Client_MonoGame.Shared` 默认求值 `net10.0;net10.0-android`。不安装 Android workload 的 Windows 专项工程在还原与构建时传入 `-p:EnableAndroidTarget=false`，只求值 `net10.0`；Android 正式构建不得关闭该属性。

### 2.1 共享构建默认值

根目录 [`Directory.Build.props`](../Directory.Build.props) 为未显式声明的工程提供 `Nullable=enable`、`ImplicitUsings=enable`、当前主版本 C# 和确定性构建默认值。遗留工程可在自身 `.csproj` 中显式覆盖；不得为了表面统一一次性开启可空性并制造大批无关告警。

测试 SDK 与 xUnit 版本也由该文件集中声明。新增测试工程引用 `$(TestSdkVersion)`、`$(XunitVersion)` 和 `$(XunitRunnerVisualStudioVersion)`，不要复制版本字面量。移动端依赖继续以 [`Client_MonoGame.Mobile.props`](../Client_MonoGame.Mobile.props) 为事实源；模块有意不同的 Roslyn 等运行依赖仍由各工程维护。

## 3. 构建

### 3.1 服务端快速内环

```powershell
dotnet restore LyoCrystal.Server.slnf
dotnet build LyoCrystal.Server.slnf --configuration Release --no-restore
```

主要运行产物位于 `Build/Server/`；依赖库也会在各工程 `bin/Release/` 下生成。`Build/` 是本地暂存输出，不是正式发布来源。

### 3.2 Windows 发布基线

```powershell
dotnet restore LyoCrystal.Windows.slnf
dotnet build LyoCrystal.Windows.slnf --configuration Release --no-restore
```

PC 客户端输出位于 `Build/src/Clients/Client_VorticeDX11/`，服务端工具可能输出到 `Build/Server tools/`。完整运行前仍需满足资源与配置要求。

### 3.3 启动器与微端

```powershell
dotnet restore LyoCrystal.Launcher.slnf
dotnet build LyoCrystal.Launcher.slnf --configuration Release --no-restore
```

启动器玩家入口为 `Launcher.PlayerShell`，GM 编辑器为 `Launcher.Editor`，微端 GUI/服务宿主为 `MicroGateway.App`。正式玩家入口必须由现有打包与签名链生成，不能把普通 `bin/` 输出当作发布物。

### 3.4 Android

普通 Release 构建：

```powershell
dotnet workload restore src/Clients/Client_MonoGame.Android/Client_MonoGame.Android.csproj
dotnet build src/Clients/Client_MonoGame.Android/Client_MonoGame.Android.csproj --configuration Release
```

正式 arm64 AOT 制品使用 CI 中的 `dotnet publish` 参数和签名流程；不要用普通本地 Debug APK 声称完成发布验收。

## 4. 测试

### 4.1 通用回归

```powershell
dotnet test Tests/Base05.Tests/Base05.Tests.csproj --configuration Release
```

Base05 是完整通用回归，可能包含耗时集成场景；局部代码修改应先运行对应筛选或专项测试，再在合并门禁运行完整集合。不得因本地等待时间较长跳过最终门禁。

历史移动协议副本的编译兼容夹具：

```powershell
dotnet build Tests/ShareProtocolCompat/ShareProtocolCompat.csproj --configuration Release
```

该工程是 Library，只证明历史 `Share` 夹具仍可编译，不是测试运行器；实际协议事实源和漂移门禁以 `Shared/`、Base05 协议测试及下方生成 manifest 校验为准。

### 4.2 Windows 集成测试

按受影响模块运行：

```powershell
dotnet test eng/WindowsIntegration/Sec01.ClientIntegration/Sec01.ClientIntegration.Windows.csproj --configuration Release
dotnet test eng/WindowsIntegration/Sec02.ClientTlsIntegration/Sec02.ClientTlsIntegration.Windows.csproj --configuration Release
dotnet test eng/WindowsIntegration/Sec02.ServerConfigIntegration/Sec02.ServerConfigIntegration.Windows.csproj --configuration Release
dotnet test eng/WindowsIntegration/Launcher.PlayerShellGateL0/Launcher.PlayerShellGateL0.Windows.csproj --configuration Release
dotnet test eng/WindowsIntegration/Launcher.PlayerShellIntegration/Launcher.PlayerShellIntegration.Windows.csproj --configuration Release
dotnet test eng/WindowsIntegration/Launcher.RemoteListIntegration/Launcher.RemoteListIntegration.Windows.csproj --configuration Release
```

CI 的通用测试任务会自动发现所有声明 `<IsTestProject>true</IsTestProject>` 的工程。新增测试工程必须显式声明该属性。

### 4.3 协议清单

修改 `Shared/` 协议事实源后必须运行：

```powershell
dotnet run --project Tools/ProtocolManifestGenerator/ProtocolManifestGenerator.csproj --configuration Release -- --write Docs/protocol-wire-manifest.generated.json
dotnet run --project Tools/ProtocolManifestGenerator/ProtocolManifestGenerator.csproj --configuration Release --no-build -- --verify Docs/protocol-wire-manifest.generated.json
```

生成清单中的读写方法哈希基于规范化 IL 语义，不直接记录会随编译环境变化的 metadata token。提交前必须审查清单差异；CI 会在 Linux Release 构建中重新生成并拒绝漂移。

CI 还会检查全部受 Git 跟踪 Markdown 文件的相对链接。新增或移动文档时，必须同步更新引用与 [`index.md`](index.md)；外部 URL 的可用性不属于该离线门禁。

## 5. 调试

### 5.1 Visual Studio

打开对应 `.slnf`，将所需宿主设为启动项目：

- 服务端：`Server.MirForms/Server.csproj`；
- PC 客户端：`src/Clients/Client_VorticeDX11/Client_VorticeDX11.csproj`；
- 玩家入口：`src/Launcher/Launcher.PlayerShell/Launcher.PlayerShell.csproj`；
- GM 编辑器：`src/Launcher/Launcher.Editor/Launcher.Editor.csproj`；
- 微端宿主：`src/MicroGateway/MicroGateway.App/MicroGateway.App.csproj`。

需要联调服务端与客户端时，在 Visual Studio 配置多个启动项目。个人启动配置写入 `*.slnLaunch.user`，不得提交；仓库中不存在可跨机器复用的服务器地址、账号或资源路径默认值。

### 5.2 CLI 启动

已满足对应配置和资源前提后可运行：

```powershell
dotnet run --project Server.MirForms/Server.csproj --configuration Debug
dotnet run --project src/Clients/Client_VorticeDX11/Client_VorticeDX11.csproj --configuration Debug
dotnet run --project src/Launcher/Launcher.Editor/Launcher.Editor.csproj --configuration Debug
dotnet run --project src/MicroGateway/MicroGateway.App/MicroGateway.App.csproj --configuration Debug
```

不要在同一个终端串行执行需要同时存活的宿主。服务端、客户端或微端需要管理员权限、端口和本地配置时，以对应运维/部署文档为准。

## 6. 资源与正式制品

仓库资源基线、授权源和 Acquire 流程见根 [`README.md`](../README.md) 的 BASE-02。常规源码修改不应执行全量 Acquire；只有资源任务或阶段末验证才运行慢外环。

| 内容 | 位置/来源 | 是否正式制品 |
|---|---|---|
| 普通工程输出 | 各工程 `bin/<Configuration>/` | 否 |
| PC/服务端本地暂存 | `Build/src/Clients/Client_VorticeDX11/`、`Build/Server/` | 否 |
| 移动启动仓库 | `Build/Mobile/BootstrapRepo/` | 仅流水线输入 |
| Android 正式包 | CI 发布工件及签名流程 | 是，门禁通过后 |
| 启动器玩家入口 | 打包、冒烟、签名后的不可变工件 | 是，门禁通过后 |

正式发布流程见 `RELEASE-*` 文档。禁止手工复制若干 DLL 或普通 `bin/` 输出后称为正式发布。

## 7. 常见边界

- 构建成功不等于资源齐全或功能验收通过。
- `Legend of Mir.sln` 用于导航，不要求单机跨平台全量构建。
- `LyoCrystal.Windows.slnf` 是发布门禁载体，不自动吸收所有 Windows 工程。
- 协议只修改 `Shared/`；不要修改移动端旧 `Share` 副本。
- 不提交 `Build/` 中未明确追踪的输出、`bin/`、`obj/`、秘密、数据库和个人 IDE 文件。
- 新增、移动或删除 `.csproj` 时必须同步 `Legend of Mir.sln`；CI 会验证集合一致性。
