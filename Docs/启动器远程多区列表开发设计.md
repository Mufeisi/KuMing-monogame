# 启动器远程多区列表开发设计

## 1. 目标与范围

本功能让 PC 启动器通过一个 HTTP/HTTPS URL 读取版本化 JSON 启动清单，在下拉列表中展示多个区服。玩家先选择区服，再点击现有“开始游戏”按钮；启动器按所选条目的游戏地址、端口和微端配置创建独立游戏实例。

本功能同时让远程启动清单发布全局补丁目录和启动器侧多开上限。它不新增 TCP 列表协议、不实现服务端反多开、不重写现有补丁器、微端、渲染或游戏网络。

本设计是独立启动器功能，不改变或宣称关闭 `Docs/PRD-PC稳定与Android发布.md` 中的任何阶段门禁。

相关领域语言见 [`../CONTEXT.md`](../CONTEXT.md)，边界决策见：

- [`adr/0001-区服选择与补丁通道分离.md`](adr/0001-区服选择与补丁通道分离.md)
- [`adr/0002-启动器保留并协调游戏窗口.md`](adr/0002-启动器保留并协调游戏窗口.md)

## 2. 已确认的产品规则

1. 清单只通过一个 `ServerListUrl` 获取，支持 HTTP 和 HTTPS，不支持 TCP 列表协议。
2. 启动器优先等待远程清单；5 秒内获取或校验失败时，依次回退有效缓存和本地单区配置。
3. 清单整体严格校验，任何字段错误、空列表或重复区服名都会拒绝整份清单。
4. 一个启动器只对应一套客户端文件，全部区服共享一个全局补丁通道。
5. 每个区服只维护名称、游戏地址、游戏端口、微端开关、微端地址、微端端口六项。
6. 地址字段同时接受 IP 和 DNS 主机名。
7. 微端启用时固定生成 `http://{microAddress}:{microPort}/api/`；微端用户和密钥继续使用本地全局配置。
8. 玩家先选区，再点击“开始游戏”；启动器记住上次选区。
9. 启动器允许独立游戏子进程多开；远程 `maxInstances` 只限制由当前启动器会话创建并跟踪的实例。
10. 游戏实例启动后启动器最小化到 Windows 任务栏，不使用系统托盘。最后一个实例退出后自动恢复启动器。
11. 游戏仍在运行时关闭启动器只会最小化；没有游戏实例时才真正退出。
12. 补丁或微端暂时不可用只提示，不阻断进入游戏。

## 3. 配置契约

### 3.1 本地配置

`Mir2Config.ini` 的 `[Launcher]` 节只新增一个远程清单地址：

```ini
[Launcher]
ServerListUrl=https://example.com/launcher.json
```

规则：

- 值为空、不是绝对 URL 或协议不是 HTTP/HTTPS 时，视为远程来源不可用，直接进入缓存与本地保底流程。
- 不自动把 HTTPS 降级为 HTTP。
- 允许 URL 使用域名、IPv4、带方括号的 IPv6 和显式端口。
- 现有 `[Network]` TLS 开关、证书名称和证书固定配置仍是全局设置，不进入远程清单。
- 现有 `[Micro] User` 与受保护的微端 Code 仍是全局设置，不进入公开清单。

### 3.2 远程 JSON

第一版固定格式：

```json
{
  "version": 1,
  "maxInstances": 3,
  "patchUrl": "https://example.com/patch/",
  "servers": [
    {
      "name": "一区",
      "serverAddress": "43.242.74.184",
      "serverPort": 7001,
      "microEnabled": true,
      "microAddress": "43.242.74.184",
      "microPort": 7777
    },
    {
      "name": "二区",
      "serverAddress": "game2.example.com",
      "serverPort": 7001,
      "microEnabled": false,
      "microAddress": "",
      "microPort": 0
    }
  ]
}
```

### 3.3 严格校验

| 字段 | 规则 |
| --- | --- |
| `version` | 必填，只接受整数 `1` |
| `maxInstances` | 必填，整数 `1`～`10` |
| `patchUrl` | 必填；允许空字符串，非空时必须是绝对 HTTP/HTTPS URL |
| `servers` | 必填，数量 `1`～`100` |
| `name` | 去除首尾空白后长度 `1`～`64`；按不区分大小写比较后必须唯一 |
| `serverAddress` | 必填；只接受无协议、无路径的 IP 或 DNS 主机名 |
| `serverPort` | 必填，整数 `1`～`65535` |
| `microEnabled` | 必填布尔值 |
| `microAddress` | 微端启用时必填 IP 或 DNS 主机名；关闭时必须为空字符串 |
| `microPort` | 微端启用时为 `1`～`65535`；关闭时必须为 `0` |

附加约束：

- JSON 使用 UTF-8，可带或不带 BOM。
- 顶层和区服条目中的未知字段、重复字段、尾随内容、注释和尾随逗号均拒绝，避免拼写错误被静默忽略。
- HTTP 响应体最大 1 MiB；超出限制按远程读取失败处理。
- 所有字符串先去除首尾空白，再进行校验与规范化。
- `patchUrl` 规范化为以 `/` 结尾，启动器固定读取其下的 `PList.gz`。
- HTTP 清单仍可用于区服选择，但不得启用远程 `patchUrl`；只有清单地址和 `patchUrl` 同时为 HTTPS 时才允许远程切换补丁源。本地 INI 中的旧补丁配置保持兼容。
- IPv6 地址用于生成微端 URL 时必须自动加方括号。

### 3.4 HTTP 与 HTTPS 安全边界

- HTTP 按需求保留，用于兼容只提供明文静态地址的部署；它不提供来源认证或传输完整性。
- HTTP 清单可能被中间人篡改区服地址，因此生产公网部署仍应优先使用证书有效的 HTTPS；HTTP 清单不能改变补丁入口。
- 启动器不检查域名备案状态；HTTPS 是否可读取取决于系统是否信任证书、访问地址是否匹配证书 SAN、证书是否有效以及网络是否可达。
- 本任务不新增清单或旧 `PList.gz` 的数字签名体系，不得把本功能描述为解决了远程补丁供应链安全。
- HTTPS 请求失败时不得自动改用同地址 HTTP。

## 4. 清单加载与缓存

### 4.1 优先级

```text
启动器启动
  → 在 5 秒超时内请求 ServerListUrl
  → 下载完成后严格解析和整体校验
      → 成功：使用远程清单，并原子更新有效缓存
      → 失败：读取并重新校验有效缓存
          → 成功：使用缓存
          → 失败：从 Mir2Config.ini 生成本地单区保底
```

远程清单已经通过校验但缓存写入失败时，本次会话仍使用该远程清单，同时记录缓存写入错误；不得因为本地磁盘问题丢弃已经可用的远程结果。

### 4.2 缓存与状态文件

启动器拥有自己的运行目录，避免把玩家选择写回游戏网络配置：

```text
Cache/Launcher/
├── RemoteLaunchManifest.json
└── LauncherState.json
```

- `RemoteLaunchManifest.json`：最后一次完整校验通过的清单及其原始列表 URL；旧版仅含原始清单的缓存可继续读取，但来源未知，不授予远程补丁权限。
- `LauncherState.json`：只保存 `lastServerName`，不保存密码、微端 Code 或其他秘密。
- 两个文件均使用同目录临时文件写入并原子替换；写入中断不得破坏旧文件。
- 读取缓存时必须执行与远程响应相同的严格校验，不能信任磁盘内容。
- 缓存清单携带当时的来源 URL、`maxInstances` 和 `patchUrl`，远程失败时作为一个完整快照共同回退；补丁授权必须使用缓存记录的来源 URL，不能使用后来修改的当前配置地址。

### 4.3 本地保底

设备上没有有效缓存时，从现有配置生成一个仅存在于内存的区服条目：

- 名称：优先使用现有 `Launcher.ServerName`，为空时显示“本地配置”。
- 游戏地址：现有 `Network.IPAddress`。
- 游戏端口：按全局 `UseTlsV2` 选择现有 `TlsPort` 或 `Port`。
- 微端：从现有 `Micro.BaseUrl` 尽力解析；无法按固定规则还原时关闭保底条目的微端。
- 补丁目录：现有 `Launcher.Host`。
- 多开上限：`1`。

## 5. 启动与补丁顺序

父进程启动顺序固定为：

1. 处理现有 `AutoPatcher.gz` 自更新接缝。
2. 加载本地 `Settings`。
3. 远程优先加载启动清单并确定本次有效快照。
4. 本地保底沿用现有补丁配置；远程或缓存快照仅在清单地址和 `patchUrl` 同时为 HTTPS 时应用到 `Settings.P_Host`，否则本次关闭远程补丁。
5. 继续复用现有 `PList.gz` 检查、差异下载和 EXE/DLL 重启流程。
6. 补丁完成或失败提示结束后启用区服下拉框和“开始游戏”。

补丁失败不阻断启动。清单加载、缓存回退和补丁检查每个启动器会话只执行一次；游戏实例退出后恢复启动器时不重复请求远程清单或检查补丁。

## 6. 启动器界面

### 6.1 控件

在现有固定尺寸和固定背景皮肤内增加一个区服下拉框，不扩宽窗口、不增加侧边栏、不改变 WebView 和补丁进度区：

- 下拉框只显示区服名称。
- 清单与补丁流程完成前禁用下拉框和“开始游戏”。
- 有上次选择且仍存在时恢复该选择；否则选择第一项。
- 选择变化只更新 `LauncherState.json`，不立即启动游戏。
- 当前存活实例数达到 `maxInstances` 时禁用“开始游戏”，并显示“已达到多开上限（当前/上限）”。
- 远程失败但回退成功时显示一次非阻断提示，说明当前使用缓存或本地配置。

### 6.2 错误提示

面向玩家的提示只说明结果和可操作建议，不展示堆栈：

- “远程区服列表读取失败，已使用上次列表。”
- “远程区服列表读取失败，已使用本地配置。”
- “区服列表配置无效，请联系管理员。已使用上次列表。”
- “补丁下载失败，可继续尝试进入游戏。”
- “已达到多开上限（3/3）。”

详细错误写入现有错误日志，包含阶段、URL 主机、HTTP 状态、异常类型和字段路径；不得记录 URL 用户信息、认证头、微端 Code 或其他秘密。

## 7. 独立游戏实例

### 7.1 进程模式

同一个 `Client.exe` 增加明确的游戏实例模式。启动器使用 `ProcessStartInfo.ArgumentList` 传递非秘密参数，避免手工拼接和转义：

```text
Client.exe --game-instance
           --server-address <地址>
           --server-port <端口>
           --micro-enabled <true|false>
           --micro-address <地址或空>
           --micro-port <端口或0>
```

游戏实例模式：

1. 跳过启动器 UI、远程清单读取、补丁检查和 `AutoPatcher.gz` 处理。
2. 正常加载本地 `Settings`，从而继承全局 TLS、微端用户和受保护密钥。
3. 严格校验启动参数后，仅在进程内覆盖本次游戏入口与微端入口。
4. 全局 `UseTlsV2=true` 时把所选端口应用到 `TlsPort`；否则应用到 `Port`。不得改变或绕过现有公网明文连接门禁。
5. 微端启用时生成 `http://{microAddress}:{microPort}/api/`；关闭时清空本进程的 `MicroBaseUrl`。
6. 运行现有预登录资源更新和 `CMain` 游戏窗体。

选区覆盖是一次性运行参数，不得写回 `Network.IPAddress`、`Network.Port`、`Network.TlsPort` 或 `Micro.BaseUrl`。保存其他玩家设置前恢复这些字段的本地原值，并通过跨进程命名互斥量串行化 INI 保存，避免多开实例同时写配置造成文件损坏。

### 7.2 实例跟踪

- 父进程只统计自己成功创建且尚未退出的游戏子进程。
- 创建失败不占用名额；子进程退出事件只释放一次名额。
- 达到 `maxInstances` 后拒绝继续创建。
- 该限制是启动器侧便利功能，不声称阻止复制客户端、直接运行或重启启动器绕过。
- 父进程异常退出时不主动终止已经运行的游戏子进程。

### 7.3 窗口生命周期

```text
启动器显示
  → 选择区服并点击开始
  → 成功创建游戏实例
  → 启动器最小化到任务栏
      → 玩家可从任务栏恢复并继续多开
      → 尚有其他实例时，单个实例退出不弹出启动器
      → 最后一个实例退出时自动恢复启动器
```

- 不创建系统托盘图标或托盘菜单。
- 有游戏实例时，启动器关闭按钮和系统关闭请求都转换为最小化到任务栏。
- 没有游戏实例时，关闭请求正常退出。
- 启动进程失败时启动器保持可见，并显示失败原因。

## 9. 验收用例

### 9.1 清单与回退

1. HTTP 与 HTTPS 清单均能读取，域名、IPv4 和显式端口均可用。
2. 远程有效时覆盖旧缓存，并正确显示全部区服。
3. 远程超时、连接失败、非成功状态、响应过大、JSON 损坏时在 5 秒后使用缓存。
4. 无缓存时从现有 INI 生成单区保底，且多开上限为 1。
5. 任一区服字段缺失、名称重复、端口越界、未知字段或空列表时拒绝整份远程清单。
6. 缓存更新中断后旧缓存仍完整可读。

### 9.2 选区与连接

1. 首次加载选择第一项；再次启动恢复上次区服。
2. 选择区服不会立即启动；点击“开始游戏”后子进程获得正确地址与端口。
3. TLS 全局开启时使用所选端口作为 TLS 端口，但保留现有证书与明文门禁。
4. 微端启用时生成预期 `/api/` URL；关闭时不沿用上一个区服的微端地址。
5. 不同区服的两个并发游戏实例各自保持独立连接与微端配置。
6. 游戏实例退出后不会把运行时选区覆盖写回 `Mir2Config.ini`。

### 9.3 补丁与多开

1. 受信任的 HTTPS 清单中 `patchUrl` 非空且同为 HTTPS 时，现有补丁器从固定 `PList.gz` 检查更新；其他远程情况跳过补丁，本地保底保持原行为。
2. 补丁失败显示提示但“开始游戏”可用。
3. `maxInstances=1` 与 `10` 的边界可用，`0`、`11` 和缺失字段会拒绝清单。
4. 达到上限后无法继续启动；任一被跟踪实例退出后释放一个名额。
5. 启动游戏后启动器只最小化到任务栏；最后一个实例退出后恢复。
6. 有实例时关闭启动器只最小化；无实例时正常退出。

### 9.4 验证命令与工件

实现阶段至少交付：

```powershell
dotnet test eng/WindowsIntegration/Launcher.RemoteListIntegration/Launcher.RemoteListIntegration.Windows.csproj --configuration Release
dotnet build Client_VorticeDX11/Client_VorticeDX11.csproj --configuration Release
```

并归档以下可见工件：

- 启动器下拉框显示两个以上区服的截图。
- 远程成功、缓存回退、本地保底三条运行日志。
- 选择两个不同区服后，两个独立游戏实例连接目标的脱敏日志。
- 达到多开上限、最后实例退出后恢复启动器的操作记录。

## 10. 明确不做

- TCP 文件列表或国产引擎私有列表协议兼容。
- 启动器系统托盘图标、托盘菜单或托盘驻留。
- 服务端账号、设备、IP 或进程级反多开。
- 每区服独立客户端、独立补丁目录或客户端目录切换。
- 在远程清单中保存账号密码、微端 Code、证书密码或其他秘密。
- 为本功能重写补丁器、微端下载器、游戏协议、渲染或资源系统。
- 把本功能扩展到 Android/iOS 启动器。
